## 4. 以后必须复用的检查规则

1. 新表先写“事实归属”，后写字段；已经有权威表时，不新增第二个可写副本。
2. 文件存在、接口定义、路由挂载、写入成功和线上验收是五种不同证据，不能混用。
3. 每个空间关联同时审查归属与记录编号；跨空间只能走明确授权关系。
4. 任何外部收费操作都考虑超时结果不明、重复执行、取消和迟到回调。
5. 迁移预案必须回答“目标已产生新数据之后怎么办”，不能只写换回连接地址。
6. 所有完成声明要写验证层级；格式检查通过不能表述成代码、性能或迁移通过。
7. 新功能同步更新总览、所属模块和受影响的横向规范，避免只在最后不断追加另一套互相矛盾的规则。

1. **<span style="font-size:18px;color:#fff">下面这7条是以后每次改动都要对照的检查清单：新表先定好这一类数据该记在哪一张权威表里，别再建一份重复的；文件里有代码、路由挂上了、真存进去了、线上验证通过，这是四件不同的事，不能混着说；跨空间关联数据必须两边都查；凡是扣钱的操作都要想到超时、重复点、取消、迟到回调这四种意外；数据迁移方案必须回答“新库开始写入后要回退怎么办”；说“做完了”必须写清是哪一级做完；加新功能时总目录和相关规矩一起改，别另写一套互相矛盾的新规矩。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">七条复用规则：先定事实归属不建第二可写副本；文件存在/接口定义/路由挂载/写入成功/线上验收是五种不同证据；空间关联同审归属与编号、跨空间走授权；外部收费操作考虑超时不明/重复/取消/迟到回调；迁移预案须回答目标已产新数据后怎么办；完成声明写验证层级；新功能同步更新总览与横向规范。</span>

## 6. 第三轮：第一性原理审查结论

本轮从“系统必须保证什么”倒推，而不是只检查表结构。新增独立文档《第一性原理与安全边界审查》，确认以下问题属于上线阻断项：代理和 Agent 网关缺少用户级鉴权与空间隔离、身份体系并存、前端保存长期密钥、计费接口与后端实现不完整、平台 API Key 明文读取、外部副作用缺少统一幂等和任务持久化。审查还补充了统一请求生命周期、失败语义、扩容边界、观测字段和第一性原理验收清单。

本轮没有修改业务代码。它的结论是：在 P0 安全和一致性问题修复并验证前，不能把代理、Agent、真实收费或团队共享当作可上线能力。

1. **<span style="font-size:18px;color:#fff">这一轮换了个问法：不问“表建得对不对”，而是问“这系统哪几件事绝不能错”。列出来一堆上线就会出事的严重问题：AI代理没验身份、两套登录并存、网页存了长期密码、计费没接完、密钥明文能读。结论是：这些严重问题修好并验证之前，代理、真实收费、团队共享都不能上线。这轮没动代码。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">第三轮第一性原理：新增《第一性原理与安全边界审查》；上线阻断项为代理/Agent 网关缺用户级鉴权与空间隔离、身份体系并存、前端保存长期密钥、计费接口与后端不完整、平台 API Key 明文读取、外部副作用缺统一幂等与任务持久化；P0 修复验证前代理/Agent/真实收费/团队共享不可上线。</span>
