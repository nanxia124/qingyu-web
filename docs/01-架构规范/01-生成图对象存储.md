# 用户生成内容与上传素材存在哪

## 1. 这是什么

**<span style="font-size:18px;color:#fff">你生成的图片、视频、音频、文本，以及提供的参考附件和手动上传的素材，都要统一保存到腾讯云。保存成功后，下次打开仍能找到。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">目标方案：全部用户生成结果及上传素材直接写入腾讯云 COS；服务器硬盘不作为正式存储、临时文件中转或失败回退。数据库保存业务记录与对象引用，浏览器只保留缓存和草稿。本文件是已确认的目标规划，尚未代表代码完成接入。</span>

## 2. 用户怎么用

**<span style="font-size:18px;color:#fff">你可以生成图片、视频、音频或文本，也可以上传参考图、参考视频、参考音频、文档等素材。生成或上传完成并保存成功后，内容会出现在对应的作品、素材或历史记录里；关掉浏览器再回来仍能查看，也能下载，分享则按授权规则办理。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">统一覆盖 AI 图片、视频、音频、文本正文，生成输入附件及用户手动上传文件；页面入口按业务类型接入。只有 COS 写入和数据库登记均确认成功，才显示保存成功。分享不等于公开存储桶，读取必须校验用户及空间权限。</span>

**<span style="font-size:18px;color:#fff">内容保存多久、删除后还能恢复多久，需要另行确定。当前不能承诺所有内容永久保存，也不能擅自增加到期自动删除规则。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">保留期限与删除恢复窗口仍是待确认产品规则，参见数据库总览第 14、16 节；本次只确定存储位置和内容范围。</span>

## 3. 数据是怎么流的

**<span style="font-size:18px;color:#fff">生成完成或收到上传内容后，直接保存到腾讯云，再登记是谁的、来自哪次生成、保存在哪里。查看时先核对权限，再读取内容；服务器不把这些内容写到自己的硬盘上。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">生成结果可经后端内存流直接写 COS；手动上传和参考附件可采用受限授权直传，或经后端内存流转发。禁止使用服务器临时文件、磁盘缓存或挂载目录作为上传中转。对象上传成功并核验后，登记 file_objects、generation_outputs 或资产关联；具体上传接口及重试实现待开发。</span>

```text
AI 生成结果 / 参考附件 / 手动上传素材
  → 直接写入腾讯云 COS（不落服务器硬盘）
  → 校验上传结果
  → 数据库登记归属、来源、文件位置和状态
  → 返回保存成功
  → 用户查看时校验权限，再读取 COS 内容
  → 最后增加访问加速，先覆盖图片
```

**<span style="font-size:18px;color:#fff">完整的文字结果也保存在腾讯云。列表可以显示简短摘要，生成时用的提示词、模型、时间和内容归属另行记录，方便查找和追溯。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">生成文本正文作为 COS 对象保存；PostgreSQL 保存任务、提示词、生成参数、摘要、对象键、文件类型、大小、校验值及工作空间归属。图片缩略图、视频封面等持久化派生文件同样写 COS，不使用服务器磁盘存储。</span>

## 4. 现在长什么样（当前实现）

**<span style="font-size:18px;color:#fff">当前代码已经有图片保存和上传素材保存的流程，但仍使用服务器硬盘。全部内容直接保存到腾讯云是这次确定的新目标，还需要开发和验证，不能当作已经上线。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">当前 object-store.mjs 默认 local，S3 实现仍为占位；api-server.mjs 的生成图片和资产上传包含磁盘写入路径。旧图片兼容读取仍存在。视频、音频、文本、参考附件和手动上传各入口均需逐项接入验收。未核实本次线上实际配置。</span>

**<span style="font-size:18px;color:#fff">已有交付记录提到腾讯云备份验证通过，但备份成功不代表新生成的内容已经直接保存在腾讯云。作品查看、下载和分享，也要按每种内容分别验证。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">COS 备份副本与业务对象主存储分开判断。历史文档描述过图片列表、大图、下载和分享入口；不能据此宣称全部内容类型已支持。直接分享到微信、微博以及 CDN 加速仍未在本规划中验收。</span>

## 5. 存在哪最好

**<span style="font-size:18px;color:#fff">已选定腾讯云保存全部内容。把大文件或完整生成正文塞进业务记录会增加查询和备份负担；放在服务器硬盘又会占用服务器空间。以后增加访问加速时，原文件仍保存在腾讯云。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">统一采用 COS 作为业务内容主存储，PostgreSQL 保存元数据与引用。CDN 是访问加速层，不替代 COS；私有内容加速仍需维持鉴权。容量、副本和备份需独立配置与验证，不承诺无限容量或绝对不丢失。</span>

| 方案 | 作用与取舍 | 当前决策 |
|---|---|---|
| 完整内容塞数据库 | 增加业务查询、传输和备份负担；旧数据需兼容 | 不作为新内容的目标方案 |
| 服务器硬盘 | 占用服务器容量，依赖磁盘及备份恢复 | 历史实现待替换；不作为新内容存储或中转 |
| 腾讯云 COS | 统一保存完整结果、参考附件和上传素材；需控制容量与费用 | 直接接入，作为正式存储 |
| CDN 访问加速 | 加快内容访问，另有配置与费用 | 最后接入，先覆盖图片；COS 保留源文件 |

## 6. 现在做到哪了

| 阶段 | 状态 |
|---|---|
| 全部生成结果、参考附件和手动上传素材统一 COS 直存 | 规划已确认，代码待实现 |
| 取消生成与上传链路的服务器磁盘写入、中转及回退 | 待实现并检查所有入口 |
| 图片、视频、音频、文本及附件的保存、读取和权限验收 | 待逐类验证 |
| 旧数据库内容与旧磁盘文件迁移到 COS | 待盘点、迁移及完整性验证；不得提前删除原件 |
| CDN 访问加速 | 放在最后实施，先覆盖图片 |

**<span style="font-size:18px;color:#fff">旧内容先核对、再搬迁，确认新位置能完整打开，才安排清理旧副本。新内容从接入后直接进腾讯云，不再增加“先存硬盘”的过渡阶段。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">历史迁移应建立对象与引用清单，核验大小、校验值、读取结果及权限后切换引用；清理旧副本需单独安排。已有 COS 备份不能替代主存储迁移验收。</span>

## 7. 出问题怎么办

**<span style="font-size:18px;color:#fff">保存失败时明确提示失败并允许重试，不能显示保存成功，也不能悄悄把内容改存服务器硬盘。已经上传但登记失败的内容，要能找回来补登记或清理，避免越积越多。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">COS 与 PostgreSQL 不能假定共享数据库事务；需设计幂等重试、未完成状态及孤立对象对账补偿。上传或登记失败必须反馈，禁止 local 磁盘或完整正文入库回退。若需回退代码，只能使用仍符合 COS 直存约束的版本，否则暂停相关写入。</span>

**<span style="font-size:18px;color:#fff">旧代码曾提供把图片改回业务记录保存的开关。这是历史机制，新方案不能继续把它当作出错后的备用保存方式。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">历史 GEN_OUTPUTS_TO_STORAGE=off 会回退到 b64_json；当前代码仍存在该分支，实施 COS 直存时需要移除或禁用新写入回退，保留必要的旧数据读取兼容。</span>

## 8. 花多少钱

**<span style="font-size:18px;color:#fff">费用取决于保存多少内容、用户看多少次，以及是否使用访问加速。视频和音频也纳入后，不能再沿用只按少量图片估算的固定月费。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">容量、请求、流量及 CDN 成本需要按内容类型与实际用量另行测算。撤销旧文档“现在 0 元、迁云后每月 10 元以内”的估算；本次不核定价格、免费额度或预算。</span>

## 9. 实施与验证入口

**<span style="font-size:18px;color:#fff">实施时要逐种内容检查：能保存、能再次打开、别人不能越权查看、失败能提示、重试不重复保存，并确认整个流程没有写服务器硬盘。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">当前代码入口：scripts/deploy/object-store.mjs、scripts/deploy/api-server.mjs、src/lib/generationTasks.ts；元数据涉及 app.file_objects、app.generation_outputs 及资产关系。历史布局 OBJECT_DATA_DIR/gen/{taskId}/{index}.{ext} 仅描述旧实现。COS bucket、region、权限、对象键及各类型入口需要实施前核实，不沿用未经确认的区域配置。必须验证 COS 及数据库失败、重试、刷新重登、权限隔离和无磁盘落盘；文档变更不代表这些测试已经通过。</span>
