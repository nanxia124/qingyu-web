# PostgreSQL 数据库迁移

目标数据库是腾讯云轻量服务器上的 `qingyu_business`。迁移文件按编号执行，先执行小编号，再执行大编号。每次执行都要在 `app.schema_migrations` 留下版本记录。

`0001_foundation.sql` 是第一版基础骨架，包含用户身份映射、空间、团队成员、角色权限、设备会话、安全审计和 outbox 事件。它不保存密码，也不包含 Appwrite 的表。

`0002_business_domains.sql` 补齐业务域：团队邀请和权限例外、订阅与订单支付、额度预占与使用流水、文件元数据、生成任务与结果、资产版本与分享收藏、点赞评论审核、供应商和模型目录、通知与隐私同意。大文件仍放对象存储，数据库只保存元数据和可追踪关系。

`0003_operational_records.sql` 补齐成员入职离职事件、个人或团队自己的 AI 渠道，以及供应商按日调用汇总。渠道只保存密钥引用，不保存浏览器可直接读取的完整 Key。

正式应用连接必须使用独立的业务数据库角色，不能长期复用 Appwrite 的 `user` 角色。前端不能直接连接 PostgreSQL；迁移、回滚和备份由服务器端受控执行。

`0004_resource_integrity.sql` 使用复合外键拦截跨空间的生成结果、资产版本和文件关联，并限制评论只能回复同一资产下的评论。文件存储身份使用 PostgreSQL 16 支持的空值相等唯一约束，避免没有存储版本号时重复登记同一个对象。

验证脚本：`tests/resource_integrity.sql`。在事务里建立两个测试空间，检查合法关联以及跨空间文件、跨资产评论、重复文件被拒绝，最后全部回滚。该脚本验证关联完整性，不代替业务鉴权或 RLS 测试。

- 真实迁移文件摘要校验、空库重放、备份、隔离恢复演练和字段数据字典尚未完成。
- 当前应用未接入这些表。不要把表数量作为全面性、隔离或上线验收证据。
