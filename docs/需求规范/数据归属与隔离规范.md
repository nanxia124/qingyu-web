# 数据归属与隔离规范

版本：0.4。状态：核心多租户边界、RLS、复合归属约束、设备会话和主要业务接口已实现并通过当前验证；完整双账号跨团队验收和所有前端页面切换仍需继续补齐。返回 [总览](数据库与多租户需求规范.md)。

当前实现依据：线上业务数据库包含 94 张表，其中 46 张启用 RLS，迁移记录为 48；团队、资产、同步、画布、Agent、生成任务、额度和会话接口已接入 PostgreSQL。空库迁移重放、跨空间约束、会话上限、任务幂等和备份恢复已验证。未列入这些证据的功能，仍按“待验收”处理。

## 1. 一项事实只有一个权威来源

“权威来源”就是两处显示不一致时，以谁为准。缓存只能从这里重建。

| 事实 | 权威来源 | 关联字段与限制 |
|---|---|---|
| 登录身份与密码 | Appwrite | user_accounts.appwrite_user_id 唯一；普通业务外键只用内部 UUID |
| 用户资料 | user_accounts | email 是联系资料，不用邮箱自动合并账号 |
| 用户偏好 | user_preferences | user_id 唯一；语言、主题等不是团队数据 |
| 个人或团队空间 | workspaces | type 与 owner_user_id、team_id 互斥；每人一个个人空间，每团队一个团队空间作为初期方案 |
| 团队所有者 | teams.owner_user_id | 必须是有效成员；转交所有权在短事务中完成；禁止最后所有者直接离职 |
| 团队成员身份 | team_memberships | (team_id,user_id) 唯一；部门和岗位必须属于同一团队 |
| 成员功能角色 | role_bindings | (workspace_id,user_id,role_id) 唯一；成员表不再保存 role_id |
| 所有者权限 | teams.owner_user_id 派生 | owner 是派生身份，不能另存可独立修改的 owner 角色绑定；其他角色按 role_bindings 读取 |
| 套餐定义与历史价格 | plans、plan_versions | 发布后的版本不可直接覆盖；功能和额度规则关联 plan_version_id |
| 空间当前订阅 | subscriptions | workspace_id、plan_version_id；每空间一个基础订阅槽，历史写 subscription_events；teams 不存 plan_id |
| 使用量与额度 | usage_records、quota_ledger | 前者记录实际使用，后者记录额度变化；不能同时作为两套可改余额 |
| 原始文件位置 | file_objects | provider、bucket、object_key、version_id（可空）、checksum、size_bytes、mime_type；不是永久签名 URL |
| 资产内容 | asset_versions、asset_files | assets 保存业务身份；asset_files 关联版本和 file_objects；不并存第二套 assets.file_id |
| 项目内容 | canvas_nodes、canvas_connections | 均关联 workspace_id、project_id；项目快照是派生版本，不另设独立写入口 |
| 任务和 Agent 历史 | generation_tasks、agent_threads 等 | 有归属、有状态、有版本；连接断开不代表任务已取消 |

平台模型目录、套餐目录、管理员身份属于平台管理范围，不强加 workspace_id。组织表以 team_id 约束；用户偏好以 user_id 约束。数据归属必须按表登记，不能笼统地说“所有表都一样”。

## 2. 防串数据的七道检查

| 位置 | 必须做到 | 大白话 |
|---|---|---|
| 登录入口 | 服务端验证身份，再映射内部 user_id；不信任请求体传来的操作者 | 不能自己填一个别人编号就变成别人 |
| 空间选择 | 前端仅提出 workspace_id；服务端检查拥有者、有效成员、封禁和操作权限 | 切换空间不是获得权限 |
| 数据访问 | 空间业务的读、写、批量操作、导出均限定已授权空间；创建归属由服务端赋值 | 不止查看时隔离，保存时也要隔离 |
| 数据关联 | 同空间父表设 UNIQUE(workspace_id,id)，子表用复合外键同时约束 workspace_id 和 parent_id | 不允许 A 空间的结果挂到 B 空间的任务 |
| 缓存与浏览器 | 私有缓存键包含环境、workspace_id、资源和权限版本；用户私有内容再带 user_id；登出和换账号清理内存及分区缓存 | 同一浏览器换账号不能看到上个账号的作品 |
| 后台任务与消息 | 持久化任务携带服务端写入的空间、用户、资源编号；执行时重新验权；SSE/消息重连、回放、审批都检查线程权限 | 后台和 Agent 不能绕过网页的门锁 |
| 文件和同步 | 文件读取先验证业务引用和权限，再签发短期地址；同步范围由账号和空间限定 | 猜到地址、恢复旧同步文件都不等于有权限 |

复合外键例子：generation_outputs(workspace_id,task_id) 必须指向 generation_tasks(workspace_id,id)。连接线两端还必须属于同一个 project_id；评论父记录必须属于同一个 asset_id。组织记录引用部门时同时校验 team_id。仅有 UUID 或单列外键不能保证这些业务关系。

按行限制读取和写入的数据库策略称为 RLS。空间业务表采用默认拒绝策略，并分别覆盖读和写；应用账号不是表所有者、超级用户，也不能有 BYPASSRLS。迁移账号与应用账号分离。每个事务设置经服务端验证的空间上下文，并在事务结束清除，测试连接池复用不会继承上个用户的空间。上下文是应用提供的第二层防线，不能代替入口认证。

用户档案、平台表、组织表分别使用所属领域规则；不能因没有 workspace_id 就默认公开。RLS 所有者绕过和外键行为以 [PostgreSQL 官方文档](https://www.postgresql.org/docs/16/ddl-rowsecurity.html) 为准。

## 3. 分享、复用和离职的明确边界

| 操作 | 所有权变化 | 撤销或离职后 |
|---|---|---|
| 个人资产授权团队查看 | 不变；asset_shares 记录源资产、目标空间、权限、到期和撤销状态 | 撤销后停止新访问；已下载文件不能远程收回 |
| 在团队项目引用个人资产 | 通过显式分享授权桥接，不伪造源资产的 workspace_id | 引用保留来源编号，展示为无权访问，不能继续签发文件地址 |
| 复制为团队独立资产 | 创建团队资产版本和受控文件副本，记录来源；须有复制权限 | 不随来源分享撤销而删除；复制规则需在产品中明示 |
| 在团队空间生成 | 任务与结果归团队，created_by 保留实际作者 | 成员离职后团队保留内容，成员权限撤销 |
| 在个人空间生成 | 任务与结果归个人 | 不因加入团队自动把个人内容交给团队 |

普通外键只允许同空间关联。跨空间共享只能经 asset_shares 等专用授权关系：源对象外键验证存在，目标空间外键验证存在，服务端验证源方有分享权和目标方有使用权。读服务只返回被授权字段，不为分享临时开放整个源空间。

离职事务至少更新成员状态、撤销角色绑定和临时授权、提升权限版本。消息订阅主动断开；后续任务与审批重新验权。已发短期文件链接在到期前可能仍可访问；要求立即撤销的资源必须经下载代理逐次校验。任务停止和外部调用结算分开处理。

## 4. 常用调用方式与适度设计

前端调用业务接口，不能直接查询数据库。初期使用模块化单体：一个后端内按业务分目录，不为每类表部署独立服务。同步事务由应用服务编排，各模块通过自己的服务写表；只有异步通知、可靠任务派发等需要 Outbox。

| 场景 | 建议接口契约 | 返回与限制 |
|---|---|---|
| 资产列表 | GET /workspaces/{id}/assets?cursor=...&limit=... | 返回摘要、next_cursor，不带原图、全部历史或密钥 |
| 保存节点 | PATCH /workspaces/{id}/projects/{projectId}/nodes/{nodeId} | 携带旧 version；冲突返回 409 和当前版本，不静默覆盖 |
| 发起生成 | POST /workspaces/{id}/generation-tasks | 带幂等键；返回已持久化的 task_id 和排队状态 |
| 读取结果 | GET /workspaces/{id}/generation-tasks/{taskId} | 重新验权；包含结果摘要和受控下载入口 |
| 文件访问 | GET /workspaces/{id}/files/{fileId}/download | 检查有效资产或任务引用、权限和文件状态 |

统一错误语义：401 未登录；403 没有操作权限；404 资源不存在或不能披露其存在；409 版本/状态/幂等冲突；429 限流。不能在失败分支展示“保存成功”。已接入的路由遵守这套语义；尚未切换到 PostgreSQL 的页面仍按待实现处理，不能仅凭表结构宣称已完成。

节点类型专用参数可存带 schema_version 的 JSONB，需字段校验、大小上限、升级转换和默认值。需要外键、唯一性、索引查询、计费计算的字段使用明确列。节点配置不为“看起来规范”强行拆表，拖拽不逐像素写数据库；按节点批量增量保存并处理版本冲突。

## 5. 文件与扩展治理

file_objects 建议公共字段为 id、workspace_id、storage_provider、bucket、object_key、storage_version_id、checksum、size_bytes、mime_type、status、created_at。状态至少 pending、ready、deleting、deleted；数据库提交和文件上传不是一个事务。上传确认后才允许引用 ready 文件；失败上传由清理任务回收。

删除先阻止新引用，再延迟清理；清理前重查有效引用和恢复窗口。删除失败可重试。数据库备份不包含对象文件，必须独立备份和校验。长期密钥保存加密引用并记录 key_version，解密钥匙不能与密文一同放入普通备份或浏览器。

| 新功能上线前登记项 | 必填内容 |
|---|---|
| 模块和事实 | 属于哪个模块、现有表能否复用、谁是唯一写入者 |
| 数据字典 | 字段中文含义、英文名、类型、必填、默认值、外键、唯一性、索引、保留时间 |
| 范围与权限 | 用户/空间/组织/平台哪一类；角色、分享、删除和导出规则 |
| 兼容升级 | 新旧应用兼容期、JSON 版本、增量脚本和回滚条件 |
| 数据生命周期 | 文件、日志、软删除、匿名化、账务保留及恢复规则 |
| 验收 | 跨账号、跨空间、重复请求、并发、失败恢复、性能和迁移测试 |

初期不统一给所有表加软删除和 version。可编辑业务实体才需要版本；账务流水只追加冲正，不通过修改和软删除纠错。系统动作记录 actor_type 和可空 actor_user_id，不能为了满足 created_by 必填伪造一个用户。

## 6. 验收门槛

当前已完成的验证包括：空库从头执行全部迁移、线上备份临时恢复、跨空间关联拒绝、额度幂等范围保护、退款金额保护、三设备会话上限、重复生成任务提交与领取、文件上传失败清理。以下门槛仍属于上线前待完成的扩大验收，不得用已有单元测试替代。

必须用两个账号、两个个人空间、两个团队和跨团队成员组合执行：替换资源 ID、篡改 workspace_id、批量混入其他空间记录、猜文件编号、修改关联父记录、重连消息、离职后调用、切换账号恢复缓存、重放离线同步。结果应为拒绝或按明确分享授权读取，不能泄露字段或产生跨空间写入。

还需用数据库应用账号直接验证非法复合外键失败、无上下文拒绝、连接池上下文不串用。以上未运行时，报告只能写“规范已定义”，不能写“已保证隔离”。
