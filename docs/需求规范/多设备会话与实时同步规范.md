# 多设备会话与实时同步规范

版本：0.6（设计稿）。范围：账号登录、设备管理、跨端同步与并发修改。本文只定义目标，不表示代码或线上配置已经完成。

## 1. 先回答实际问题

| 问题 | 当前证据 | 目标要求 |
|---|---|---|
| 一个账号能登录几台？ | 本地前端没有业务设备上限；线上 Appwrite 配置未核实 | 建议初始允许 5 个有效登录会话，做成可配置规则；不是已经生效的数字 |
| 能看到设备记录吗？ | 已查登录 Store 没有设备列表流程 | 安全中心显示设备名称、最近活动、登录时间、当前设备、有效/已撤销状态 |
| 能远程退出吗？ | 当前只有退出当前会话 | 支持退出指定会话、某设备全部会话、退出其他会话；敏感操作要求再次验证身份 |
| A 操作后 B 会更新吗？ | 现有本地存储与 WebDAV 合并不能保证实时更新 | 服务端保存成功后通知 B，B 按权限读取最新数据；离线时明确提示未同步 |
| 两台同时改会不会乱？ | 时间戳合并不能证明无覆盖 | 检查数据版本；冲突时保留草稿并提示处理，不能静默覆盖 |
| 允许登录 5 台就是能同时跑 5 个任务吗？ | 不能如此推导 | 会话数、实时连接数、任务并发数、团队席位分别控制 |

“设备”在网页中通常只能近似识别为一个浏览器配置或客户端安装。同一台电脑用两个浏览器可能占两个名额；同一浏览器多个标签页通常共用一次登录。不能承诺准确识别物理硬件。

## 2. 当前代码审查与依据

| 位置 | 观察到的行为 | 局限与处理 |
|---|---|---|
| `src/stores/useAuthStore.ts` | 使用 Appwrite 创建登录会话、读取账户、删除 current 会话；持久化前端登录摘要 | 登录摘要不是鉴权凭据；每次业务请求仍须服务端验证 |
| 同上 logout | 删除会话失败后仍清空前端状态 | 本地退出和服务端撤销必须区分；失败不能显示“所有设备已安全退出” |
| `src/canvas/services/app-sync.ts` | WebDAV 清单交换；部分数据按 updatedAt/createdAt 合并 | 不是数据库事务、权限撤销通道或可靠实时同步；时钟偏差和并发上传可能覆盖更新 |
| `src` 中会话与订阅检索 | 未找到完整设备列表、远程会话撤销和通用跨端事件流程 | 静态检索不等于验证线上所有能力；Agent 流式输出和本地 Store 订阅不等于业务同步 |

核对 [Appwrite 官方会话安全说明](https://appwrite.io/docs/advanced/security/authentication)：其会话上限可配置，超限创建会话可能删除最旧会话。因此“满额后让用户选择退出哪台”不能仅靠 Appwrite 默认行为实现。部署版本和实际控制台配置仍需核实。

## 3. 模块与权威来源

```text
账号与安全
├── Appwrite：密码、身份验证、身份会话
├── PostgreSQL：业务准入、设备摘要、撤销记录、安全审计
└── 安全中心：设备列表、退出、风险提示
业务数据
├── PostgreSQL：已保存数据、版本号、可靠事件
├── 文件存储：图片和视频本体
└── 浏览器：按账号和空间隔离的缓存、待提交草稿
同步通道
├── 通知有变化：SSE 或 WebSocket，按实际需要选一种
├── 拉取最新数据：带权限检查的 API
└── 重连补齐：游标、快照、重复消息去重
```

Appwrite 会话有效且业务准入有效，才允许业务访问。业务会话不复制密码或另造一套账号。设备编号只用于展示关联，不能证明身份；请求中的 user_id、workspace_id、device_id 都不能直接信任。

## 4. 登录数量与操作规则

| 规则 | 规范 |
|---|---|
| 计数对象 | 未过期、未撤销且已获业务准入的登录会话；关闭网页不等于退出 |
| 上限来源 | 平台账号策略，可有明确的账号级覆盖；不能把多个团队套餐相加得到个人上限 |
| 建议默认值 | 5；上线前需产品定稿并检查 Appwrite 上限配合情况 |
| 满额行为 | 建议拒绝新增业务准入，进入受限设备管理流程；再次验证后选择替换。受限身份不能访问业务数据 |
| 并发登录 | 服务端按用户串行化名额分配；两个同时登录请求不能一起越过最后一个名额 |
| 登录中途失败 | 临时名额有超时；创建身份会话与业务准入不能当作跨系统原子事务，失败需补偿清理 |
| 下调上限 | 明确选择保留会话并撤销其余，不能留下长期超额状态；规则变更留审计 |
| 在线显示 | 近期有心跳才显示“最近在线”；后台休眠或断网不等于会话无效，不把最近活动当精确在线证明 |
| 退出与任务 | 普通退出不自动取消已提交任务；异常封禁阻止新动作，并按任务取消规则处理已有任务 |
| 团队管理员 | 能移除成员及团队权限，不能因此管理成员个人账号的所有设备 |

满额选择流程必须在实施时统一登录入口并验证身份提供方行为。直接调用 Appwrite 新建会话仍可能触发其淘汰规则；在解决这个冲突前，不能承诺“绝不自动挤掉旧设备”。

## 5. 数据字典与约束

下表是新增领域的逻辑字段。物理建表时还需确定长度、保留期和迁移文件。内部 ID 为 UUID，时间为 UTC timestamptz。允许为空的字段在解释中注明。

### 5.1 `user_devices`：设备展示摘要

| 字段 | 类型 | 大白话与约束 |
|---|---|---|
| id / user_id | UUID | 记录编号 / 所属账号；user_id 外键指向 user_accounts |
| installation_id | UUID | 浏览器安装标记；唯一键 (user_id,installation_id)，可被清缓存重置，不作为安全凭据 |
| display_name | text | 用户可改的设备名称；限制长度并按普通文本显示 |
| client_type / os_family / browser_family | text | Web/桌面等和系统浏览器摘要；属于提示信息，允许 unknown |
| created_at / last_seen_at | timestamptz | 首次登记 / 最近活动；最近活动降频更新 |
| archived_at | timestamptz，可空 | 历史摘要归档；不代替会话撤销 |

### 5.2 `user_sessions`：业务准入与撤销

| 字段 | 类型 | 大白话与约束 |
|---|---|---|
| id / user_id / device_id | UUID | 会话编号、用户、设备；(user_id,device_id) 复合外键防关联到别人的设备 |
| identity_provider / provider_session_id | text | Appwrite 会话引用；提供方范围应包含项目，二者组合唯一；不保存会话密钥 |
| admission_status | enum | pending/active/denied；是否允许使用业务功能 |
| created_at / expires_at / last_seen_at | timestamptz | 创建、有效期、活动；业务有效期不能长于身份会话有效期 |
| revoked_at / revoked_reason | 时间/枚举，可空 | 已撤销的事实与原因；终态不能重新变为 active |
| admitted_auth_version | bigint | 获准时账号安全版本；与 user_accounts.auth_version 不符即失效 |
| provider_revocation_status | enum | not_requested/pending/succeeded；身份提供方是否也完成撤销 |
| revoke_retry_at / revoke_attempts | 时间可空/整数 | 撤销失败的重试时间和次数；达到告警阈值交运营处理 |

`user_accounts.auth_version` 为非负整数，退出全部设备、账号异常封禁或恢复安全操作时递增。它是账号级撤销版本，不是可编辑资料的 version。指定会话退出只更新对应会话。有效性由状态、过期时间、撤销事实与安全版本共同判断，不持久化另一个易过时的 is_online/is_valid。

推荐索引：user_sessions(user_id,created_at)、有效准入会话的 user_id 部分索引、provider_session_id 唯一索引、待重试撤销时间索引。名额限制不能仅靠索引实现，还需账号级事务锁或等价并发控制。

### 5.3 复用记录，避免重复建账

| 现有实体 | 本模块使用内容 |
|---|---|
| security_events | 登录、准入拒绝、撤销、异常设备；关联 user_id、session_id、操作者、原因、结果、request_id、发生时间；不记录密码或 Token |
| audit_logs | 管理员操作与策略变更；团队管理员只能查看授权团队范围的审计 |
| outbox_events | 在业务事务内保存待通知事件；复用统一投递机制，不另建一套同步事实库 |
| 可编辑业务实体的 version | 防止两台设备互相覆盖；账户安全版本与业务版本不能混用 |

设备摘要和安全记录的保留天数尚未定稿；上线前必须配置。IP、完整 User-Agent 应最小化收集、限制访问，并按独立保留期清理。已撤销会话的拒绝依据至少覆盖旧凭据可能有效的时间及恢复窗口，不能过早删除后自动准入。

## 6. 撤销必须在服务器生效

1. 服务端验证当前身份与操作权限；“退出其他会话”以验证过的当前会话为排除项，不能相信前端随意传入的保留编号。
2. 在事务内记录业务撤销和安全事件；全部退出时递增账号安全版本。新业务请求和敏感写入提交前检查有效性。
3. 在对应账号或成员记录上采用一致的锁顺序，使撤权和写入有确定先后。撤权前已经提交的操作不因退出自动撤销；撤权后开始的新操作必须拒绝。
4. 通知所有实时节点断开目标连接，同时请求 Appwrite 撤销对应身份会话。提供方失败进入重试，业务端继续拒绝，不能因提供方仍有效再次自动建立准入。
5. 前端清理该账号缓存、停止订阅、取消未提交请求，显示退出结果。撤销确认失败时明确“本地已退出，服务器撤销未确认”，提供再次处理入口。

长连接不仅握手时验权；发送受限内容前也要检查当前授权，撤权事件需到达所有节点。缓存失效故障时走权威校验，无法校验则停止受保护访问，不能继续使用无限期旧权限。

不能收回用户已经下载的文件或看过的内容。短期签名下载链接也可能在剩余有效期内可用；要求立即撤销的资源应走鉴权下载入口。离线设备不能保证当场清除缓存，因此应限制敏感数据离线保留，并在重连时先验权、再同步。

## 7. 哪些东西同步到哪里

| 数据 | 范围 | 行为 |
|---|---|---|
| 个人资料、个人偏好、收藏 | 本人各会话 | 服务端保存后刷新；个人收藏不因此公开给团队 |
| 团队资产、评论、点赞 | 当前仍有资源权限的成员 | 只向获准订阅者发事件，不能按团队编号直接广播完整内容 |
| 生成任务与结果 | 对该任务有权限的会话 | 同步持久化任务状态；退出网页不丢任务；进度可合并，结果不可丢 |
| 订阅、额度、预占与结算 | 有权限的本人或团队账务角色 | 从服务端读取，不在每台设备独立加减余额 |
| 成员移除、权限变更 | 受影响会话 | 撤销访问、断开订阅、清除相关缓存；优先级高于普通刷新 |
| 页面位置、画布缩放、光标 | 默认当前设备 | 不强制把另一台跳到同一页面；协作光标属于可丢的临时消息 |
| 密码、密钥、完整凭据 | 不广播 | 只发送“安全设置有变化”等无敏感信息通知 |

## 8. 保存、推送、补齐的可靠流程

1. 客户端发操作编号、资源编号、预期版本和变更内容。服务端从身份推导用户并检查空间及资源权限。
2. 在一个事务里修改业务事实、递增资源 version、写 outbox；提交后才向用户确认“已保存”。文件上传尚未归档时须显示处理中。
3. 投递器发送 event_id、schema_version、事件类型、授权范围、资源编号、resource_version。消息以最小通知为主，客户端再带身份读取数据。
4. 客户端按 event_id 去重，只应用更新版本；旧的网络响应也不能覆盖新状态。账号或空间切换后，丢弃旧上下文返回的请求。
5. 断线后用服务端签发的不可猜测重放游标补齐。游标必须绑定身份和授权范围，不能使用 A 空间游标读 B。
6. 游标过期、事件缺口、权限变化或恢复备份后，重新鉴权并获取一致快照。先建立可续传订阅位置再读取快照，或使用服务端保证无缝的快照加游标协议，不能在快照与订阅之间漏数据。

数据库自增序号不保证事务提交顺序，不能直接用“上次最大序号”跳过尚未提交的事件。实施时采用可证明无缺口的持久投递序列与重放协议，并覆盖事务逆序提交测试。不同资源不要求全局顺序；同一资源以 version 判新旧。

补齐窗口和最大积压量必须配置。慢客户端不能让服务器无限排队，应断开并要求快照重同步。事件至少一次投递，因此重复消息是正常情形；不能因此重复执行生成、扣款、通知业务副作用。

## 9. 两台同时修改与离线操作

| 场景 | 正确处理 |
|---|---|
| 两台都读取版本 8，再修改同一资源 | 第一台成功成为版本 9；第二台带版本 8 提交返回 VERSION_CONFLICT，保留它的草稿并展示差异 |
| 改不同画布节点 | 以可独立修改的节点或明确操作为粒度；不要上传整张旧画布覆盖其他人的新节点 |
| 同一节点同时改 | 明确冲突提示或经过验证的字段合并；不能用设备时间自动选赢家 |
| 离线期间另一台删除 | 保留删除事实；旧草稿上传不能复活已删除资源；需要时另存为新资源并重新验权 |
| 点赞与收藏重试 | 设置“已点赞/已收藏”这种目标状态，不用重复 toggle；唯一键保证同一用户同一目标只有一条 |
| 断网重试生成 | 同一次意图使用同一幂等键；真正新建任务使用新键；幂等作用域含操作者、空间和操作类型 |
| 离线余额或订阅 | 只能展示缓存提示；预占、付款、审批等操作必须在线由服务端确认 |
| 账号切换 | 草稿、请求队列、事件游标按 user_id/workspace_id 隔离；不能把前一账号草稿自动提交给后一账号 |

“多端看到最新保存结果”是本期同步目标。“多人同时拖拽且自动合并每一步”是更高一级协作能力；如以后需要 CRDT（自动合并并发编辑的数据结构）或操作变换，须独立设计与验证，不能用当前时间戳合并冒充。

## 10. 接口与页面契约（规划）

| 入口 | 作用与权限 |
|---|---|
| GET /me/sessions | 列本人分页会话；不返回凭据，返回当前会话标记、设备摘要和撤销状态 |
| POST /me/sessions/{id}/revoke | 本人撤销指定会话；重复操作返回相同结果，越权目标不可操作 |
| POST /me/sessions/revoke-others | 再次验证后退出其他登录；服务端确定当前会话 |
| POST /me/sessions/revoke-all | 再次验证后退出全部，包括当前；恢复、封禁也走一致撤销服务 |
| 业务 PATCH 接口 | 必须携带 expected_version；权限失败拒绝，版本冲突返回可恢复的冲突提示 |
| 实时订阅与重放接口 | 验证会话、空间、资源范围；限制连接和订阅数量；游标失效返回重新同步提示 |

统一错误语义：SESSION_REVOKED 已退出、SESSION_LIMIT_REACHED 名额已满、PERMISSION_DENIED 无权限、VERSION_CONFLICT 修改冲突、SYNC_RESET_REQUIRED 需重新同步。不要把网络故障一律显示为密码错误。

安全中心需有：空列表、加载失败、当前设备、疑似设备摘要、撤销处理中、提供方撤销待重试。编辑器需有：未保存、保存中、已保存、离线草稿、冲突待处理。只有服务器确认后才能显示已保存。

## 11. 性能、恢复与扩展边界

- 建议健康网络、在线前台设备的同步延迟目标为 p95 不超过 2 秒，从服务端提交到另一端显示计时；这是待压测目标，不是当前保证。后台休眠、断网须单独统计。
- 心跳仅放短期状态，数据库 last_seen_at 降频写；初期单实例可用内存，扩容后用共享临时存储。心跳丢失不删除业务记录。
- 通知优先传小事件；任务进度合并发送、列表分页，图片视频走文件存储。不能每次点赞刷新整个团队所有数据。
- 复用既有 outbox；PostgreSQL 是业务事实来源。引入 Redis 不改变扣款、权限和版本的权威来源。
- 恢复备份后更新恢复代次，废弃旧同步游标、连接与旧任务执行资格；结合撤销记录防止旧登录和已删除数据复活。参照[备份回滚恢复执行规范](备份回滚恢复执行规范.md)。
- 迁移托管 PostgreSQL 保留用户、空间、资源 UUID 和版本；身份系统不因搬业务数据库自动切换。切换时客户端重连重新同步，不能把迁移当作无断线保证。
- 新功能登记数据所有者、授权范围、版本策略、事件类型、删除行为和重放规则；事件 schema_version 保持兼容。禁止新增绕过统一鉴权与同步协议的私有通道。

## 12. 实施顺序与验收

P0 先修复统一鉴权、空间隔离、业务服务端持久化和会话撤销；P1 再做设备中心、版本冲突和可靠通知；P2 才考虑精细在线状态、协作光标和复杂自动合并。Web 是当前必需端；桌面和移动端将来复用契约，不能据此宣称现在已经实现。

| 编号 | 验收操作 | 必须看到的结果 |
|---|---|---|
| S01 | 名额只剩一个时同时登录两台 | 只有一个获得新准入，失败会话和临时名额可清理 |
| S02 | 撤销一台后用其旧凭据调用 API 和长连接 | 新业务操作被拒；不能重新自动准入；其他会话按预期保留 |
| S03 | Appwrite 撤销失败、通知丢失 | 业务拒绝仍生效，撤销可重试并告警；页面不虚报全部撤销成功 |
| S04 | A 用户改订阅、B 用户猜事件或资源编号 | B 得不到 A 的数据；团队内无财务权限成员也不能获得账务详情 |
| S05 | 两台基于旧版本改同一内容 | 发生明确冲突，无静默丢失；草稿仍可找回 |
| S06 | 消息重复、乱序、事务逆序提交、断网重连 | 最新状态正确且没有遗漏；无重复任务和扣费 |
| S07 | 快照期间有并发写入、游标过期 | 能补齐或重新取快照，不出现永久旧状态 |
| S08 | 移除成员、切换账号后旧请求晚到 | 旧数据不再写入当前界面或缓存；离线草稿不能越权上传 |
| S09 | 备份恢复、服务重启、多实例滚动升级 | 旧游标可识别失效；撤销不复活；已保存任务可查 |
| S10 | 大团队通知和慢客户端压测 | 内存/队列有上限；按真实连接数与事件速率测延迟，不只看注册用户数 |

监控项：活跃准入会话数、拒绝次数、撤销待重试数量、事件积压时间、重放失败率、同步延迟、版本冲突率。原始用户编号只在受控审计中使用，避免把高基数个人信息塞进监控标签。

发布采用开关和小范围验证。通知系统故障时降级为明确提示的定期拉取；版本校验、权限校验、服务器保存确认不能关闭。前端回滚需兼容已有事件和接口，不能重新启用旧的整份覆盖同步写主库。

## 13. 尚未验证的事项

本轮完成代码静态检查、官方会话规则核对和规范补充，没有改变登录行为、部署配置或数据库。待确认项包括线上 Appwrite 版本与上限、会话可靠绑定方式、满额登录入口、记录保留期、具体重放窗口与真实容量。以上验收表是以后实施的检查清单，本轮未运行这些功能测试。
