# 生成的图片存在哪

## 1. 这是什么

用户在我们网站上 AI 生图之后，生成的图片要长期保存，下次打开"我的作品"还能看到。这个文档讲图存在哪、怎么存最好。

## 2. 用户怎么用

- 用户在生图页写提示词，点"生成"
- 几秒钟后图出现在页面上
- 关掉浏览器，下次再打开，点"我的作品"，图还在
- 图可以下载到本地，可以分享给别人
- 图不会自己消失，除非用户手动删除

## 3. 数据是怎么流的

1. **<span style="font-size:18px;color:#fff">你点"生成"那一刻，图就存在服务器上了，不是只在你屏幕上亮一下就没。系统还记着每张图的编号、归属和存在哪。所以你关掉浏览器、明天再翻"我的作品"，那张图还在老位置。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">用户点生成 → 后端调用上游 AI 模型 → 上游返回一张图 → 后端把这张图存成文件 → 数据库记一行"第 N 张图，文件名叫 xxx" → 用户刷新页面，后端从文件里读出发给他看</span>


```
用户点生成
  → 后端调用上游 AI 模型
  → 上游返回一张图
  → 后端把这张图存成文件
  → 数据库记一行"第 N 张图，文件名叫 xxx"
  → 用户刷新页面，后端从文件里读出发给他看
```

## 4. 现在长什么样（当前实现）

打开"我的作品"页面，能看到过去生过的所有图，一行一行列出来。点开任意一张，大图展示在中间，旁边有"下载"和"分享"按钮。

**已经做了的**：
- ✅ 生图完成后图自动存下来，不依赖浏览器
- ✅ 关掉浏览器再打开，图还在
- ✅ 老用户以前生的图也能看到（自动兼容老数据）

**还没做的**：
- ❌ 图还是存在自己服务器硬盘上，没搬云存储
- ❌ 图加载速度一般，没接 CDN
- ❌ 图不能直接分享到微信/微博，只能下载后自己发

## 5. 存在哪最好

1. **<span style="font-size:18px;color:#fff">老办法是把图片文件直接存在记录里——记录会越来越大、越查越慢，备份也越来越大。所以图片要单独存，记录里只存图片的编号。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">塞进数据库（老办法）：代码简单；缺点是库胖 33%，列表越查越慢，备份越来越大</span>


2. **<span style="font-size:18px;color:#fff">存在自己服务器硬盘上不花钱，现在就是这么干的；但硬盘会塞满，万一硬盘坏了，里面的图就全没了。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">存在自己服务器硬盘：不花钱，现在就在这么做；缺点是磁盘会满，硬盘坏了图就没了</span>


3. **<span style="font-size:18px;color:#fff">存在云存储上，容量大装不满，自动留好几份副本，坏一份还有别的，不占自己服务器的磁盘；每月花几块钱就够。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">存在腾讯云对象存储：无限扩容、多副本不丢、不占自己磁盘；缺点是要花钱（每月几块钱）</span>


4. **<span style="font-size:18px;color:#fff">再快一步就是用 CDN 加速，在全国各城市都有节点，你点哪张图就从离你最近的节点立刻调出来，秒开；但 CDN 费用比云存储高。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">存在 CDN 上：用户看图最快；缺点是比对象存储贵</span>


| 方案 | 优点 | 缺点 |
|---|---|---|
| 塞进数据库（老办法） | 代码简单 | 库胖 33%，列表越查越慢，备份越来越大 |
| 存在自己服务器硬盘 | 不花钱，现在就在这么做 | 磁盘会满，硬盘坏了图就没了 |
| 存在腾讯云对象存储 | 无限扩容、多副本不丢、不占自己磁盘 | 要花钱（每月几块钱） |
| 存在 CDN 上 | 用户看图最快 | 比对象存储贵 |

**规划**：先用自己硬盘（已做完），下一步搬腾讯云，以后接 CDN。

## 7. 出问题怎么办

1. **<span style="font-size:18px;color:#fff">新装的存图流程万一出问题，可以拨一下开关让它退回老方式（图先临时存在记录里），重启就恢复原样，等修好再换回来。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">后端有个开关 GEN_OUTPUTS_TO_STORAGE=off，加上重启就回到老办法（图塞数据库）。新方案出 bug 就这么回退。</span>


后端有个开关 `GEN_OUTPUTS_TO_STORAGE=off`，加上重启就回到老办法（图塞数据库）。新方案出 bug 就这么回退。
