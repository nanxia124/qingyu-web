# 数据完整性与风险处理清单

版本：0.5。日期：2026-09-23。状态：架构覆盖审查，不是全量建表脚本或已实施清单。返回 [总览](数据库与多租户需求规范.md)。

## 1. 什么才叫“记录合理且全面”

每项记录需要明确：事实是什么、属于谁、谁可读写、如何唯一识别、与什么对象关联、状态如何变化、失败怎么恢复、多久保留、怎么备份、用什么测试证明正确。只有表名齐全不算全面。

记录分五类：业务事实（订单、作品）、权威配置（价格版本、权限）、派生数据（统计、缓存）、临时状态（连接）、审计证据（操作原因）。前三者不能混成可互相覆盖的余额或权限；临时状态丢失不应丢业务事实。审计不是完整事件溯源，不能承诺凭摘要日志重建全部数据库。

## 2. 模块覆盖与剩余缺口

| 模块 | 已有规划 | 本轮发现或仍需补齐 | 实施前验收 |
|---|---|---|---|
| 用户身份 | Appwrite 映射、内部 UUID、个人空间 | 身份验证失败、并发首次登录、注销重新注册、新账号不得继承旧账号资料 | 冒充 ID 拒绝；重复初始化不产生双空间 |
| 团队组织 | 成员、部门、岗位、所有权 | 部门循环引用禁止；转交所有权和邀请席位并发约束；邀请令牌只存哈希、单次使用、到期 | 两人抢最后席位不超员；跨团队部门引用失败 |
| 权限与分享 | 空间角色、复合外键、RLS | 明确封禁/离职优先拒绝；角色不得跨空间绑定；公开令牌撤销与签名链接寿命 | 分享不能授予原操作者没有的权限 |
| 订阅与计费 | 价格版本、支付、流水、预占 | 本轮补发放批次和分配；税费、退款、到期、争议、部分成功计价需产品确认 | 批次过期解冻不能多发额度 |
| 生成与 Agent | 任务、尝试、线程、审批 | 供应商成本和用户收费分离；审批绑定不可变参数哈希、审批人、期限与一次性消费 | 审批后更换命令不能沿用旧批准 |
| 文件与资产 | 版本、对象元数据、引用 | 生成输出、Agent 附件、头像均需受控引用；删除清理覆盖全部引用，不仅 asset_files | 文件仍被任务或头像使用时不得删 |
| 画布与同步 | 节点、连接、版本、冲突 | 离线旧权限不能写入；导入 ID 重映射和父子关系校验；同步删除墓碑 | 导入不能覆盖同 ID 的其他空间对象 |
| 插件与渠道 | 来源、版本、密钥边界 | 检查源 URL 重定向、私网访问和执行权限；校验和只能证明内容未变，不能证明可信 | 非受信插件不能读其他空间或平台密钥 |
| 收藏、评论、反馈 | 基本表和关系 | 收藏可见性、评论父项同资产、审核历史、失败重试和封禁处理 | 分享撤销后收藏不继续暴露内容 |
| 通知与事件 | Outbox、去重 | 消费失败、事件版本升级、最小必要负载；邮件外部副作用不得假定可事务回滚 | 重放事件不重复发权益 |
| 删除与导出 | 生命周期、墓碑、临时导出 | 按数据类别确认保留期、备份过期、合法保留及撤权；不承诺物理即时删除全部备份 | 恢复后不复活删除内容和旧授权 |
| 运维恢复 | 迁移步骤、RPO/RTO 目标 | 本轮补备份目录、日志链、独立收件箱、恢复代号、密钥与灾难演练 | 新环境无生产副作用，恢复后账务不重放 |

上表“已有规划”不是“字段已经全部定稿”。所有 P0 表仍需在实施前形成逐字段字典：类型、长度、空值、默认值、主外键、唯一约束、索引、审计字段、保留期和删除行为。未定规则必须保持对应功能关闭，不能用默认值偷偷决定真实扣费行为。

## 3. 少存和多存都可能出问题

| 选择 | 规则 |
|---|---|
| 余额与流水 | 允许余额作为事务内维护的派生值加速查询；流水可重算，二者一致性受检查，不能都任意编辑 |
| 任务参数与目录 | 目录保存当前配置，任务保留提交时的安全参数/价格快照；这是有意保存历史，不是重复主数据 |
| 文件地址 | 存对象标识和版本；签名 URL 临时生成，不把凭据和过期 URL 当永久事实 |
| 日志与原始响应 | 最小化和脱敏；大响应设大小/保留期，密钥永不记录；财务证据不能只存不可追踪的错误字符串 |
| 文件去重 | 初期按空间隔离存储；不因全局 checksum 相同就共享授权或回收生命周期 |
| 统一通用表 | 不使用一张 resource_type/resource_id/JSON 表替代所有强关系；多态引用需有明确校验与孤儿扫描 |
| 动态扩展 | 可变配置用有版本 JSONB；资金、权限、关联和常用查询列必须受类型及约束保护 |

## 4. 风险处置顺序

P0：身份与空间隔离、平台 Key 保护、无额度拒绝、原子预占、任务持久化、异机备份与恢复、真实支付验签与对账（开放收费前）。

P1：批次有效期和退款规则（相关套餐上线前）、离线同步、分享撤销、审批绑定、精确导出删除、插件和自定义渠道边界（相关入口开放前）。优先级数字不能让已开放功能绕过必要安全验收。

P2：依据实测引入读副本、分区、独立队列和分析库。不能靠这些组件弥补缺失的权限、幂等和恢复规则。

本轮不认定任何未知风险已完全排除。上线证明必须来自权限、并发、故障注入、账务核对与恢复演练；仅多审几轮文档无法代替实施验证。
