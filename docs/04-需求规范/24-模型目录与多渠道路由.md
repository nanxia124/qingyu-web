# 模型目录与多渠道路由

## 这是什么

管理员在后台配置好供应商地址和 key，然后手动决定用户能看到哪些模型名字、每个名字背后实际跑哪个供应商的模型。多个供应商挂在同一个名字下面，用户请求进来时自动挑一个最空闲的供应商走，减少排队。

## 为什么这么做

一个供应商同时能接的请求数有限，所有人都走同一条道会排队。挂多条道进去，用户自动走空的道，网站整体并发就上去了。

## 怎么用的

1. **<span style="font-size:18px;color:#fff">先在"API 渠道"里加供应商：填地址和 key，点按钮拉取这个供应商有哪些模型，勾选你要用的，保存。这一步只是告诉系统"这个渠道能提供哪些上游模型"，不会自动在前台创建任何模型条目。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">platform_api_keys 表存渠道配置（name、provider、base_url、api_key、model 逗号分隔列表）；POST /api/admin/fetch-models 从供应商 /v1/models 拉取模型列表；保存渠道时 syncPlatformChannelModels() 只维护 model_catalog_channel_models 关联，不自动 INSERT model_catalog 条目（2026-09-26 改）。</span>

2. **<span style="font-size:18px;color:#fff">再去"模型目录"点"添加目录模型"，填一个前台给用户看的显示名字（比如"快速生图"），选能力类型（图片/视频/文本/音频）。这一步只建一个空壳，不关联任何供应商。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">model_catalog 表存目录条目（id、display_name、provider=unknown、capability、visible、sort_order）；POST /api/admin/models-catalog 创建条目，model_id 为 null。用户积分价及计价单位单独设置，不取供应商成本价。</span>

3. **<span style="font-size:18px;color:#fff">展开这个目录条目，点"添加渠道模型"，从你在第 1 步勾选过的上游模型里挑几个，关联到这个显示名字下面。一个显示名字可以挂多个上游模型。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">model_catalog_channel_models 表存关联（model_catalog_id、platform_api_key_id、upstream_model_id、priority、is_active）；POST /api/admin/models-catalog/:id/channels 建立关联。同一目录下的渠道请求协议（openai/gemini）必须一致。</span>

4. **<span style="font-size:18px;color:#fff">前台用户只看到你在第 2 步填的显示名字。用户发请求时，后端从这个名字挂的多个上游模型里挑一个调用；这个名字背后实际跑哪个供应商，用户看不到也不需要知道。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">listPublicModelCatalogChannels() 只返回 visible=true 且有激活渠道关联的目录项；findChannelForModel() 根据 catalog:N 查关联路由，选一个 channel+model 代理调用。</span>

### 用中转站批量接入（MaiziAI）

5. **<span style="font-size:18px;color:#fff">如果用的是 MaiziAI 这种聚合中转站，不用手动一个个填地址和 key。先在"API 与模型 → 内置供应商"页填一次中转站地址和 key，就能查里面还剩多少钱、看中转站有哪些模型和价格、看中转站公告。然后回到"API 渠道"页点"添加"，选"内置供应商"，系统自动把地址和 key 带过来，你只需要勾要哪几个模型、起个名字，保存就建好一条渠道。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">MaiziAI 供应商配置存于 billing settings.supplier.maizitech（baseUrl、apiKey、balanceToken）；接口 GET /api/admin/billing/supplier/{balance,key-limits,models,announcements}；内置供应商配置面板位于 AdminDashboard 的 supplier Tab（独立 Tab，不与 channels 列表混在一起）。添加渠道时选 builtin 模式，POST /api/admin/api-keys 用 maizitech 的 baseUrl/apiKey 作为凭证，model 为用户勾选的中转站模型 id 逗号拼接，provider=openai，max_concurrency=5。不再提供"一键全量同步"按钮，只能在添加弹窗里勾选模型。原 AdminBillingPage 的"API渠道"标签页已删除。</span>

## 路由策略

5. **<span style="font-size:18px;color:#fff">一个显示名字背后挂了多个渠道时，请求挑当前最空闲的渠道发；某个渠道连接失败或超时，自动换另一个渠道重试，用户基本感觉不到某个渠道挂了。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">2026-09-26 实现：findChannelForModel() 按 priority 排序后，同 priority 组里用 channelInflight Map 选当前在跑请求最少的渠道（least-connections）；proxyRequest 里 dispatchRequest() 在连接错误/超时时，如果还没写响应给客户端，自动调 findChannelForModel 选另一个渠道重试，最多换 2 次。实时代理路径已生效；异步生图/生视频任务的重试后续再加。熔断（连续失败暂时摘除渠道）留到以后。</span>

6. **<span style="font-size:18px;color:#fff">渠道关联里的 priority 数字越小越优先。正常情况下先走 priority 小的渠道，它忙不过来或挂了再走下一级。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">model_catalog_channel_models.priority 整数，ORDER BY priority, id 排序；listPlatformModelRoutes() 返回排序后的路由列表。</span>

## 什么时候用得到

- 新接一个供应商：先加渠道、拉模型、勾选保存，再去目录建显示名字、关联上游模型
- 某个供应商变慢或挂了：在目录里把对应的渠道关联移除或设为不活跃，用户自动走其他渠道
- 想给用户换个模型但不想改前台文案：改目录条目背后关联的上游模型即可，显示名字不变

### 用户积分价格

1. **<span style="font-size:18px;color:#fff">建好模型后，要另外填写用户使用一次要扣多少积分、按什么单位计算。供应商价格是平台成本，不能直接当成用户积分价。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">后台 Model Catalog 编辑 creditPrice 和 creditPriceUnit；支持 request、output、second、thousand_chars。保存价格时递增 credit_price_version 并写入 model_credit_price_history；报价和任务锁定用户确认时的价格版本。</span>


2. **<span style="font-size:18px;color:#fff">模型没有用户积分价时，页面会提示暂时不能按平台积分生成；管理员补好价格后，用户才能看到预计费用。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">/api/billing/quote 只对已配置 credit_price 与 credit_price_unit 的目录模型出价；客户端不提交自算金额。实际用户价仍待按模型配置，0068 迁移尚未应用到本地/生产数据库。</span>

## 现在长什么样

- ✅ API 渠道配置：填地址 key、拉模型列表、勾选保存
- ✅ 内置供应商（MaiziAI）独立 Tab：配置中转站凭证、查余额/模型价格/公告；添加渠道时可选"内置供应商"模式自动带凭证、勾选模型
- ✅ 模型目录手动添加显示名称、手动关联上游模型（不再自动创建）
- ✅ 前台只显示目录条目，不暴露真实供应商
- ✅ 路由按渠道当前负载选最闲的，连接失败/超时自动换渠道重试（实时代理路径）
- ✅ 本地代码已支持给模型单独设置用户积分价和单位、记录改价版本，并由服务端报价；仍需应用 0068 迁移并为每个模型录入实际价格
- ⚠️ 视频、音频及画布面板已加入报价/余额提示；连接上游文本的画布配置节点及 Agent 触发流程还需实际验收，未覆盖的页面不得宣称已完成
- ⚠️ 仅通过 TypeScript/Vite 构建与 Node 语法检查；数据库迁移、真实生成、扣分/退款对账和生产部署尚未验证
- ✅ 生图任务失败自动换渠道重试一次；视频/音频任务的换渠道重试和渠道熔断后续再加

## 后续升级方向

按优先级排：

1. **<span style="font-size:18px;color:#fff">生图任务失败后自动换渠道重试一次，不用用户手动点重试。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">2026-09-26 实现：runGenerationTaskWorker 里 callUpstreamImage 返回非 2xx 或抛异常时，自动调 findChannelForModel 选一个不同渠道再试一次（最多重试 1 次）；轮询上游 task_id 也用新渠道。生图路径已生效；视频/音频任务的换渠道重试后续再加。</span>

2. **<span style="font-size:18px;color:#fff">后台加渠道健康看板，一眼看到每个渠道成功率、平均响应时间、最近失败次数。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">基于 usage_records 和 generation_attempts 聚合统计，在管理后台展示每个 platform_api_key 的成功率、延迟、失败原因分布；现在靠手动试判断渠道好坏。</span>

3. **<span style="font-size:18px;color:#fff">连续失败的渠道暂时摘下来，过几分钟自动放回去试，不让用户反复往坏渠道发请求。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">在 channelInflight 旁加一个 channelFailureCounts Map，连续失败 N 次后标记为熔断状态，冷却期内 findChannelForModel 跳过该渠道，冷却结束后放一个探测请求试。</span>

4. **<span style="font-size:18px;color:#fff">渠道质量按明确的会员权益和平台成本规划，不能给新用户加每日免费次数。新用户只一次性获得 50 积分，积分用完后需要订阅才能继续生成。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">当前路由尚未按会员等级实施分组策略；如未来按用户权益选择渠道，资格判断应依据已确认的订阅/积分规则，不依赖 daily free quota。供应商成本只用于平台成本管理，不改写用户确认的积分报价。</span>

5. **<span style="font-size:18px;color:#fff">同一个显示名称下如果有多个渠道，可以按权重分配流量，不是谁闲走谁。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">model_catalog_channel_models 加 weight 字段，priority 相同的渠道按权重比例分流（如 70/30），而不是纯按负载平均。</span>
