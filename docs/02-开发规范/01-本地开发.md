# 本地开发怎么跑、怎么登录

## 1. 这是什么

1. **<span style="font-size:18px;color:#fff">这是在你自己电脑上跑一个跟线上网站一样的测试环境，里面没有真实用户、没有真实数据。你随便改、随便删，都不会影响正在用网站的人。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">一套在本地跑网站代码的方法，用 docker 起空数据库，不碰生产数据；docker postgres 在 5433，后端在 3001，前端在 5173。</span>

## 2. 干什么用的

让你在自己电脑上改代码、看效果，随便造数据、随便删表，都不影响线上真实用户。

## 3. 怎么用的

1. **<span style="font-size:18px;color:#fff">按顺序开三样东西：先开数据库，再开后端，最后开前端；三样都起来后，浏览器打开一个专门地址就自动登录，不用输密码。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">第一步开数据库 docker start qingyu-local-db；第二步开后端 node api-server.mjs（带本地连接参数）；第三步开前端 npm run dev；第四步浏览器开 5173/api/dev-login 自动登录（自动设简体中文）</span>


**第一步：开数据库**
```powershell
docker start qingyu-local-db
```

**第二步：开后端**
```powershell
cd D:\qingyu-web\scripts\deploy
$env:PGHOST='localhost'; $env:PGPORT='5433'; $env:PGUSER='user'
$env:PGPASSWORD='qingyu_local_dev'; $env:PGDATABASE='qingyu_business'
$env:BILLING_STORE='postgres'; $env:DEV_LOGIN='1'
node api-server.mjs
```

**第三步：开前端**
```powershell
cd D:\qingyu-web
npm run dev
```

**第四步：登录**
浏览器打开 `http://localhost:5173/api/dev-login`（**必须是 5173，不能是 3001**），自动登录跳首页。

> 为什么不能用 3001：3001 和 5173 是两个端口，浏览器认为是两个网站，登录信息互不相通；在 3001 页面写好的登录态，跳到 5173 就丢了。5173 会经 vite 代理把请求转给后端，但页面本身属于 5173。

*（AI: container qingyu-local-db postgres:16; env BILLING_STORE=postgres DEV_LOGIN=1 GEN_OUTPUTS_TO_STORAGE=on; vite proxy /api→3001 /v1→prod; dev-login sets billing_token/token/appwrite_uid/auth-store(isLoggedIn)/dev_login=1/locale=zh-CN; checkSession 见 dev_login=1 直接 return，不查 Appwrite）*

## 4. 什么时候会用到

- 改完代码要在自己电脑上看效果
- 测新功能、改 bug
- 不敢直接上生产验证的时候

## 5. 是不是最优解

是。微软、各家 SaaS 都这么干：本地空库 + dev-only 登录接口。比连生产库安全，比每次输密码方便。

*（AI: refs Microsoft Learn mock signed-in state during local development）*

## 6. 优点、缺点

**优点**：不碰生产数据、启动快、一键登录
**缺点**：本地数据是测试的，跟线上真实数据有差别，有些场景要手动造数据

## 7. 最佳推荐

每次开发前按顺序：docker start → 开后端 → 开前端 → 浏览器开 dev-login。别用网页登录框。

## 8. 前置条件

- Docker Desktop 装着并且在跑
- 代码已经拉到 D:\qingyu-web
- 第一次跑要先 `npm install`（根目录和 scripts/deploy 各一次）

## 9. 出问题怎么办

| 症状 | 怎么办 |
|---|---|
| 登录页弹 Invalid Origin | 别用登录框，直接开 dev-login 地址 |
| 页面出现英文/繁体混杂 | 重新开一次 `http://localhost:5173/api/dev-login`，会自动重置为简体中文 |
| 后端起不来说端口被占 | 关掉旧 node 进程再开 |
| docker start 报容器不存在 | 容器被删了，要重建 |
| 数据库连不上 | 确认 docker 容器是 running 状态 |

*（AI: EADDRINUSE 用 Get-NetTCPConnection -LocalPort 3001 找 PID 杀掉；新容器要先跑 scripts/deploy/_init_roles.sql 建 qingyu_app/qingyu_api/qingyu_admin role，再跑 database/migrations/*.sql）*
