# 数据库交付记录

## 这次到底做了什么

当前系统还没有正式用户，所以本次没有搬运旧用户数据，也没有删除 Appwrite 的身份数据。做的是建立一套新的业务数据库结构，并把安全边界和关键数据规则写进去。

数据库更新文件里的“迁移”指的是更新空数据库的表、字段、索引、约束和函数。它不是把用户从一个数据库搬到另一个数据库。将来如果真的更换托管 PostgreSQL，才需要另做数据备份、导入、校验和切换。

## 现在的数据安全规则

普通业务账号 `qingyu_app` 不能登录数据库，也不是管理员。它只能在后端事务设置当前用户身份后访问自己的空间内容。数据库会再次检查空间归属，所以只隐藏前端按钮不能绕过隔离。

身份、团队成员、角色权限、支付、额度账户、供应商密钥、审计和迁移记录不能由普通账号直接增删改。以后这些动作要通过后端受控事务完成，避免“把 A 的成员改到 B 的团队”或直接把额度改大。

额度不会只靠一个 `balance` 数字覆盖写入。每次预占、成功结算、失败释放都会留一笔流水；重复请求使用幂等键返回同一结果。账户更新使用行锁，防止两个并发请求同时花掉同一份额度。

## 已实际验证

以下测试均在服务器上的真实 PostgreSQL 执行，测试数据在事务结束时回滚：

- `database/tests/rls_isolation.sql`：只能读取自己的空间，不能写入 B 空间；没有身份时默认拒绝。
- `database/tests/privilege_boundary.sql`：普通账号不能直接写身份、成员、权限、支付、配额和审计表。
- `database/tests/resource_integrity.sql`：跨空间文件、收藏条目、资产引用、点赞、跨资产评论和重复文件会被拒绝。
- `database/tests/prompt_integrity.sql`：跨空间提示词来源和标签关联会被拒绝。
- `database/tests/plan_version_integrity.sql`：订单套餐和价格版本不一致时会被拒绝。
- `database/tests/asset_share_integrity.sql`：分享目标类型和对象存在性会被校验。
- `database/tests/payment_idempotency.sql`：待付款去重、支付金额校验和已付款订单不可回退。
- `database/tests/billing_consistency.sql`：预占幂等、额度不足拒绝、结算、释放和额度守恒。
- `database/tests/agent_governance.sql`：Agent 轮次唯一性和基础关联。
- `database/tests/backup_catalog.sql`：备份校验和、验证状态和恢复演练结果可追踪。
- `database/tests/sessions_realtime.sql`：多设备会话记录和撤销其他会话。
- `database/tests/organization_lifecycle.sql`：团队成员角色边界和部门层级防环。
- 付款接口使用幂等编号：重复点击、网络超时重试和重复支付回调都会复用原订单；已经付款的订单再次请求会返回成功结果，权益只发放一次。
- 服务器实际备份：`qingyu_business` 已生成 PostgreSQL custom 备份，SHA-256 校验通过，记录的版本为 `0019_payment_idempotency`。
- 服务器实际恢复演练：备份已恢复到临时隔离库，恢复后核对到 83 张 `app` 表和 `0019_payment_idempotency`，随后删除临时库；RPO 记录为 0 秒，RTO 记录为 4 秒。
- 服务器定时备份：`qingyu-business-backup.timer` 已启用，每天 03:30 UTC 自动执行；刚刚已手动触发一次并确认备份记录为 `succeeded`，文件 SHA-256 与数据库记录一致。

## 还没有假装完成的部分

目前业务前端还没有全面切换到这套表。成员邀请、角色变更、支付回调、退款、供应商真实扣费、异机备份副本、空库重放校验和字段数据字典仍需继续实现。服务器本地定期备份已经启用，但它不能代替异机副本和上线前的完整验收。表数量不能代替这些验收。

SSH 服务器端已把未登录等待从 420 秒降到 60 秒，并提高握手余量、开启连接保活；配置先通过语法检查再平滑 reload。偶发的“TCP 已连接但 banner 超时”仍可能来自外部网络链路，部署脚本应使用 10 秒超时和重试，不能把一次连接失败当成数据库失败。
