## 这次到底做了什么

当前系统还没有正式用户，所以本次没有搬运旧用户数据，也没有删除 Appwrite 的身份数据。做的是建立一套新的业务数据库结构，并把安全边界和关键数据规则写进去。

数据库更新文件里的"迁移"指的是更新空数据库的表、字段、索引、约束和函数。它不是把用户从一个数据库搬到另一个数据库。将来如果真的更换托管 PostgreSQL，才需要另做数据备份、导入、校验和切换。

4. **<span style="font-size:18px;color:#fff">这里说的"迁移"不是把用户已有的数据从一个地方搬到另一个地方，而是把空的记录表、字段和规则都建好；等以后真要换存放数据的地方，才需要备份、导入、校验和切换。</span>**<br>

## 现在的数据安全规则

API 服务现在使用独立的非超级账号 `qingyu_api` 连接 PostgreSQL；它不能创建数据库、创建角色或修改数据库结构，密码只保存在服务器环境文件中。`qingyu_app` 继续保留为受限数据库角色，用于权限测试和受控函数。由于现有服务代码仍有一部分直接查询业务表，`qingyu_api` 当前临时启用了 `BYPASSRLS`，空间归属由后端每个查询的用户条件和业务权限校验保证；后续把全部写入收敛到受控函数后，再关闭 `BYPASSRLS`，恢复纯数据库行级安全。

5. **<span style="font-size:18px;color:#fff">连接业务库的那个账号只能读和写业务数据，不能建库、建角色或改库结构；它的密码只保存在服务器的环境配置里，不放在前端。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">API 服务现在使用独立的非超级账号 qingyu_api 连接 PostgreSQL；它不能创建数据库、创建角色或修改数据库结构，密码只保存在服务器环境文件中。</span>


身份、团队成员、角色权限、支付、额度账户、供应商密钥、审计和迁移记录不能由普通账号直接增删改。以后这些动作要通过后端受控事务完成，避免"把 A 的成员改到 B 的团队"或直接把额度改大。

6. **<span style="font-size:18px;color:#fff">你的会员身份、在哪个团队、能看哪些图、花了多少钱，这些重要记录不能由普通账号直接改，必须走受控流程。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">身份、团队成员、角色权限、支付、额度账户、供应商密钥、审计和迁移记录不能由普通账号直接增删改。</span>


额度不会只靠一个 `balance` 数字覆盖写入。每次预占、成功结算、失败释放都会留一笔流水；重复请求使用幂等键返回同一结果。账户更新使用行锁，防止两个并发请求同时花掉同一份额度。

7. **<span style="font-size:18px;color:#fff">你的剩余额度不是只记一个数字，每次花、每次退都有一笔流水账；同一个请求点两次，结果一样不会扣两次钱；两个人同时花钱，系统会排队，不会把同一块钱花两次。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">额度不会只靠一个 balance 数字覆盖写入。每次预占、成功结算、失败释放都会留一笔流水；重复请求使用幂等键返回同一结果。账户更新使用行锁，防止两个并发请求同时花掉同一份额度。</span>

## 新增数据关联的维护规则

- 涉及空间的关联应同时校验对象编号和空间编号，不能只检查对象存在。
- 拒绝测试必须核对具体约束；不能把重复编号导致的失败当作空间隔离通过。
- 本轮额度分配测试覆盖同空间成功、跨空间使用记录拒绝、跨空间额度批次拒绝；测试数据均回滚。
- 备份恢复成功只证明这份备份能恢复和基础结构存在，不能代替全部业务流程验收。
