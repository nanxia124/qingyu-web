# 本地开发怎么跑、怎么登录

## 1. 这是什么

1. **<span style="font-size:18px;color:#fff">这是在你自己电脑上跑一个跟线上网站一样的测试环境，里面没有真实用户、没有真实数据。你随便改、随便删，都不会影响正在用网站的人。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">一套在本地跑网站代码的方法，用 docker 起空数据库，不碰生产数据；docker postgres 在 5433，后端在 3001，前端在 5173。</span>

## 2. 干什么用的

让你在自己电脑上改代码、看效果，随便造数据、随便删表，都不影响线上真实用户。

## 3. 怎么用的

1. **<span style="font-size:18px;color:#fff">先用 Docker 打开本地数据库和后端，再打开前端；最后访问本地登录地址，就能免密码进入测试网站。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">在项目根目录运行 docker compose -f docker-compose.dev.yml up -d，再运行 npm run dev；浏览器访问 http://localhost:5173/dev-login。Docker Compose 启动 qingyu-local-db 和 qingyu-local-api，Vite 将本机登录请求代理至本地 API。</span>


**第一步：开本地数据库和后端**
```powershell
cd D:\qingyu-web
docker compose -f docker-compose.dev.yml up -d
```

**第二步：开前端**
```powershell
cd D:\qingyu-web
npm run dev
```

**第三步：登录**
浏览器打开 `http://localhost:5173/dev-login`，成功后会自动进入首页。请用电脑本机的 `localhost` 地址，不要用局域网 IP，也不要直接访问 3001 端口。

2. **<span style="font-size:18px;color:#fff">打开上面的地址就会自动登录，不用注册，不用输入账号密码。平时使用的是本地演示账号，和正式网站上的账号没有关系。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">默认身份为 local-dev-user，邮箱为 local-dev-user@local.dev。src/pages/DevLoginPage.tsx 请求 /api/dev-login?format=json 并携带本机 installationId；后端在本地 PostgreSQL 创建或复用用户及设备会话，以 HttpOnly Cookie 保存业务登录票，前端只保存演示身份和 dev_login 标记。</span>


3. **<span style="font-size:18px;color:#fff">检查时说的“独立本地测试账号”，只是为了不影响你正在使用的演示账号而另外创建的测试账号。你不用找它的密码，也不用切换过去，日常仍然打开专用登录地址即可。</span>**<br>

4. **<span style="font-size:18px;color:#fff">本地没装普通账号的登录服务时，网页登录框会提示暂时不能使用，不会偷偷借用正式网站登录。开发专用入口仍可使用，但不能用它代替注册、找回密码或第三方登录的测试。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">未配置本机 VITE_APPWRITE_PROXY_TARGET 时，Vite 的 /v1 HTTP 请求返回 503 和“未配置本地身份服务”提示，Realtime WebSocket 也被拒绝；Appwrite SDK 保留错误消息，AuthModal 展示该消息。普通账号功能需要独立的本地 Appwrite 服务；docker-compose.dev.yml 当前只提供业务 API 与 PostgreSQL，不能据此认为已安装 Appwrite。</span>

> 登录页地址是 `/dev-login`；它会通过 5173 的本地代理请求后端。免密登录只在本机开发环境开放，局域网访问和生产环境不会开放这个入口。3001 是后端端口，不要把它当作网站地址。

## 6. 优点、缺点

**优点**：不碰生产数据、启动快、一键登录
**缺点**：本地数据是测试的，跟线上真实数据有差别，有些场景要手动造数据

## 7. 最佳推荐

每次开发前按顺序：运行 `docker compose -f docker-compose.dev.yml up -d` → 运行 `npm run dev` → 浏览器打开 `http://localhost:5173/dev-login`。开发登录有问题时，先确认这两个服务都已启动，再刷新登录地址。

## 8. 前置条件

- Docker Desktop 装着并且在跑
- 代码已经拉到 D:\qingyu-web
- 第一次跑要先 `npm install`（根目录和 scripts/deploy 各一次）

## 9. 出问题怎么办

| 症状 | 怎么办 |
|---|---|
| 登录页显示 not found | 确认打开的是 `http://localhost:5173/dev-login`，并确认本地 Docker 后端已启动；不要用局域网 IP 或 3001 端口 |
| 登录页弹 Invalid Origin | 别用网页登录框，直接开 `http://localhost:5173/dev-login` |
| 页面出现英文/繁体混杂 | 检查网站语言设置；重新打开 `http://localhost:5173/dev-login` 登录 |
| 后端起不来说端口被占 | 关掉旧 node 进程再开 |
| docker start 报容器不存在 | 容器被删了，要重建 |
| 数据库连不上 | 确认 docker 容器是 running 状态 |
| 网页登录框提示“未配置本地身份服务” | 日常开发打开 `http://localhost:5173/dev-login`；只有测试普通账号功能时才另行配置本地登录服务，禁止改为正式网站地址 |
| 视频页一直提示“请先登录”，或已完成的视频没有显示 | 在同一个 `http://localhost:5173` 浏览器里重新打开 `http://localhost:5173/dev-login`，登录后再进入视频页；如果账号已登录仍无法读取，检查视频任务请求是否带上本地登录 Cookie，并确认前端没有用管理端登录凭据替代普通用户会话 |
| 启动时报“只允许本机地址”或“禁止连接远程” | 检查环境变量和本地环境文件，去掉远程地址，改成本机或允许的本地容器地址；不要绕过检查 |
| 新设置没有生效 | 重启本地前端；容器环境设置变更后重新运行 `docker compose -f docker-compose.dev.yml up -d`，单纯改文件不会更新正在运行的容器环境 |
| 页面红条报 `JSON.parse: unexpected end of data at line 1 column 1`，后台数字全是 0 | Docker 后端容器没在跑。跑 `docker start qingyu-local-api qingyu-local-db`，等几秒再刷新页面。这不是代码坏了，是后端没人接请求，前端解析空响应失败 |
| 后台报 `bind message supplies 2 parameters, but prepared statement "" requires 1` | SQL 语句里用了几个 `$1`、`$2` 占位符，代码就得传几个参数；多传少传都会报这个错。查 `postgres-billing-store.mjs` 里对应的函数，数清楚参数个数 |
| 后台报 `xxx is not a function` | 函数在 `postgres-billing-store.mjs` 里定义了，但没加到文件末尾的 `return { ... }` 导出列表里。把函数名补进去，再 `docker restart qingyu-local-api` |
| 改了 `scripts/deploy/` 下的代码不生效 | 容器是把整个 `scripts/deploy` 目录挂载进去的，改完文件要重启后端容器：`docker restart qingyu-local-api`，前端不用重启 |
| 管理后台登录报"请求来源不受信任，请刷新页面后重试" | 本地前端端口因为 5173 被占自动跳到了 5174、5175 等端口，后端现在放行 localhost 任意端口；改完后端代码后 `docker restart qingyu-local-api` 即可，不用清 cookie、不用切端口 |
| 后台页面报 `column mc.xxx does not exist` 或类似"字段不存在" | 本地数据库落后于代码了，要跑新迁移。在项目根目录用 PowerShell 把对应 SQL 文件喂进数据库容器：`Get-Content -Raw database\migrations\00XX_xxx.sql -Encoding UTF8 | docker exec -i qingyu-local-db psql -U user -d qingyu_business -v ON_ERROR_STOP=1`，跑完刷新页面。迁移文件按编号从小到大跑，已跑过的会自动跳过 |

*（AI: EADDRINUSE 用 Get-NetTCPConnection -LocalPort 3001 找 PID 杀掉；新容器要先跑 scripts/deploy/_init_roles.sql 建 qingyu_app/qingyu_api/qingyu_admin role，再跑 database/migrations/*.sql）*

## 本地与生产必须隔离

1. **<span style="font-size:18px;color:#fff">在自己电脑上开发和检查时，不允许连接本项目的正式服务器。发现本地服务没开，要启动本地服务或明确报错，不能改成借用正式网站。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">用户明确约束：本地开发禁止连接生产服务器，包括生产 HTTP、SSH、生产数据库及生产身份服务；本轮没有部署、轮换生产 SSH 凭据或核查生产防火墙。生产运维不属于本地开发流程。</span>


2. **<span style="font-size:18px;color:#fff">本地服务地址填错时，网站会停下来告诉你，不会继续向远程服务器发请求；本地登录完成后也只回到当前电脑上的页面。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">vite.config.ts 对 serve 模式（含 preview）的 VITE_API_PROXY_TARGET、VITE_APPWRITE_PROXY_TARGET、VITE_API_URL 检查进程环境及 .env 文件；只接受 HTTP(S) 的 localhost、127.0.0.1、[::1] 根地址，拒绝凭据、查询参数及远程目标。API 默认指向 127.0.0.1:3001；身份服务无生产默认回退。useAuthStore.getOAuthOrigin 在 DEV 或本机 hostname 下返回 window.location.origin，忽略正式 OAuth 回调配置。</span>


3. **<span style="font-size:18px;color:#fff">后台也会检查要连接的地址，只有本机和指定的本地服务能通过。普通开发不允许直接填远程服务器地址。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">非 production 环境：APPWRITE_INTERNAL_URL 仅允许 HTTP(S) 的 localhost、127.0.0.1、[::1]、appwrite、host.docker.internal，禁止 URL 内嵌凭据；PGHOST 默认 127.0.0.1，仅允许 localhost、127.0.0.1、::1、db、qingyu-local-db、host.docker.internal，并在模块载入时检查。开发 API 容器内部通过 API_HOST=0.0.0.0 接收端口映射，宿主机仍限 127.0.0.1:3001；生产 API 固定监听 127.0.0.1。容器名按项目本地网络配置使用，不能用来指向生产。</span>
