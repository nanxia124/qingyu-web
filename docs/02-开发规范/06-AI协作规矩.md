# AI 协作规矩

## 铁律（任何其他规矩不得压过）

1. **<span style="font-size:18px;color:#fff">只在当前项目文件夹里活动，不许翻外面的文件。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">只在项目根目录内搜索、查看、操作文件；不许查看或修改项目目录以外的任何内容。</span>

2. **<span style="font-size:18px;color:#fff">改文件前必须先问清楚：要做什么、改哪些文件、每个文件改什么、影响多大。等我说"开始"才动手。我说"选 A""按 C 来"只是定方向，不算授权。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">动手前必须拿到明确指令：用户说"开始/动手吧"之前一个字都不改；"选方向"不等于"授权动手"。</span>

3. **<span style="font-size:18px;color:#fff">没看懂、有争议、我没说清楚的，立刻停下来问，不许自己猜着做。修 bug、报错、急活也一样。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">有歧义、有争议、没理解用户想法时必须停下问清楚；修 bug、报错、紧急情况不豁免。</span>

4. **<span style="font-size:18px;color:#fff">读文件、查状态这些看看的事随时可以做，但看完不能顺手就改，得回头重新申请开工。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">只读调查（读文件、查状态、Grep/Glob）随时可做，但调查完必须回到"动手前必须拿到明确指令"重新申请。</span>

5. **<span style="font-size:18px;color:#fff">不许打比方。直接说事实、说后果、说界面上能看到什么。觉得我听不懂，就把句子拆短换词重说，不许编"就像""好比"这种类比。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">严禁使用"就像""好比""相当于""打个比方"等类比句；听不懂就拆短重说。</span>

## 界面规矩

1. **<span style="font-size:18px;color:#fff">默认不加描边，除非我特意要求。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">禁止 border/描边，除非用户特意要求。</span>

2. **<span style="font-size:18px;color:#fff">保持双主题，不主动改配色。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">保持双主题，不主动改配色方案。</span>

3. **<span style="font-size:18px;color:#fff">界面上给用户看的文字必须走多语言，不能硬写死中文。新增文案要在语言文件里加，不要在组件里写死。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">用户可见文案必须走 i18n，新增文案在语言文件里加，不在组件里硬编码中文。</span>

## 干活流程

1. **<span style="font-size:18px;color:#fff">说人话：给方案、汇报进度、说问题时，先讲清"我在界面上能看到什么、为什么之前坏了、有啥后果"。服务器命令、文件路径、函数名、接口名不许写进正文，实在要提就放最后"技术备注"里。要我拍板的事，讲清几个选项分别意味着什么，别只甩名词。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">服务器命令、文件路径、函数名、接口名一律不写进正文，非写不可放"技术备注"；需要用户决策时讲清各选项含义。</span>

2. **<span style="font-size:18px;color:#fff">讲方案必须带代价：给选项、做技术决定时，优点和缺点分条列出来，有几条列几条，不限数量；安全隐患没有就直接写"没有"，不许空着、不许只说好处。列完后必须给一个最佳推荐。纯事实问答不用硬凑。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">给方案必须分条列优点、缺点（不限数量），安全隐患无则明写"没有"；列完必须给最佳推荐。</span>

3. **<span style="font-size:18px;color:#fff">动手前先读相关文件、确认当前状态，不凭记忆直接改。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">先看现状再改，不凭记忆替换。</span>

4. **<span style="font-size:18px;color:#fff">每次只改一小块（一个函数、一个组件、一个接口），改完立刻跑一遍检查（编译、页面刷新），没问题再继续。出问题能快速定位到刚改的那几行。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">小步快跑：每次改一小块，改完立刻跑 TypeScript 编译和页面刷新验证。</span>

5. **<span style="font-size:18px;color:#fff">AI 能自己做的事直接做，不要列步骤让我手动操作。跑命令、改代码、查日志、杀进程、重启服务这些 AI 直接干。只有 AI 确实做不了的才找我：要登录密码、要扫码、要付钱、要我在浏览器里点按钮、要我提供 AI 看不到的信息。删数据、上线、改核心逻辑这类关键操作，做之前还是要先跟我确认。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">AI 能做的直接做（跑命令、改代码、查日志、杀进程、重启服务）；只有需要密码、扫码、付费、用户手动操作浏览器、用户提供不可见信息时才找用户；删数据、上线、改核心逻辑等关键操作仍需先确认。</span>

6. **<span style="font-size:18px;color:#fff">本地 localhost 和线上站严格分开，不混。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">严格区分本地 localhost 和生产 litzone.art。</span>

7. **<span style="font-size:18px;color:#fff">我说要统一某样东西时，必须把项目所有相关文件逐行读一遍，不许跳过、不许漏。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">"统一"=全项目逐行审，所有相关文件逐行检查。</span>

## 代码规矩

1. **<span style="font-size:18px;color:#fff">组件命名写全称，不用缩写。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">组件命名清晰，不用缩写。</span>

2. **<span style="font-size:18px;color:#fff">删除、关闭、开启这类关键操作，必须弹确认框。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">关键操作（删除、关闭、开启）必须有确认弹窗。</span>

3. **<span style="font-size:18px;color:#fff">头像、图标用默认映射，别每个单独配。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">头像、图标优先用默认映射，不单独配置。</span>

4. **<span style="font-size:18px;color:#fff">保存、删除、切换、提交这些写操作，完成后必须弹 toast 反馈，成功失败都要弹。toast 统一用 antd 的 App.useApp() 的 message，别混用其他组件。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">所有写操作必须有 toast 反馈；统一用 antd App.useApp() 的 message。</span>

## 部署

1. **<span style="font-size:18px;color:#fff">前端改动（src 下的 tsx/ts/css）：push 到 main 后，GitHub Actions 自动构建并部署到 nginx。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">git push origin main → GitHub Actions 自动部署。</span>

2. **<span style="font-size:18px;color:#fff">后端改动（scripts/deploy/api-server.mjs）：push 后还要手动 scp 到生产服务器并重启 node 进程。服务器是 ubuntu@43.160.249.6，接口路径在 ~/qingyu-api/api-server.mjs。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">后端 push 后需手动 scp 到 ubuntu@43.160.249.6:~/qingyu-api/api-server.mjs 并重启 node。</span>

## 文档规矩

1. **<span style="font-size:18px;color:#fff">写 docs 下任何文档前，先读 docs/README.md 的"写白话的规矩"和"改动后怎么写入规范"。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">写 docs/ 前必读 docs/README.md 的格式规范和写入流程。</span>

2. **<span style="font-size:18px;color:#fff">代码改完先让我测试，我确认没问题后，主动问"要不要写入规范？"，我回"可以写入"才按"白话大字+专业小字"格式写。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">流程：改完→用户测试→确认→主动询问→用户同意后写入。</span>

3. **<span style="font-size:18px;color:#fff">需求文档里"现在长什么样"必须跟着进度同步更新，不能一直留着"还没开始""下一步做 XX"这种过时话。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">需求文档"现在长什么样"一节必须同步更新为实际完成状态。</span>

## 计费额度

1. **<span style="font-size:18px;color:#fff">新用户注册赠分数由管理员在后台设置；设为 0 就暂停赠分。改完只影响之后注册的新用户，已经到账的积分不变。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">注册赠分的唯一配置源由后端保存；新账号创建时读取当前值并按用户编号幂等发放。后台写入必须经过管理员鉴权、范围校验和审计。</span>
