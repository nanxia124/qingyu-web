# 设备登录冲突确认规范

版本：0.1（2026-09-26 草稿，待实现后回填"现在长什么样"）。范围：新设备登录时与正在线设备的确认流程，以及被挤下线时的提示。

### 这是什么

规定一个账号在另一台设备已经在用时，新设备登进来该怎么办——不再一声不吭把旧设备挤掉，而是两边都弹框问一下。

1. **<span style="font-size:18px;color:#fff">你在电脑上正用着，突然有人用另一台设备登你的号。系统不会立刻把你踢下去，而是先问你："有台新设备要登，允许吗？"你不点允许或拒绝，就一直挡在你面前。新设备那边也会看到"另一台正在用，要切过来吗"，它不确认就进不来。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">新设备登录检测到已有在线会话时，不立即接管；新建会话为 admission_status='pending'，双方通过确认接口决定结果。在双方确认前，新会话不能调用业务接口。</span>


### 用户怎么用

- 新设备登录时，如果已有设备在线，新设备弹框显示旧设备是什么，让你选"切到这台"或"取消"
- 正在线的旧设备同时收到弹框，显示新设备是什么，让你选"允许并下线本机"或"拒绝"
- 旧设备的弹框是强制的，不点不能继续用；里面还会提醒"如果不是你本人登录，可能密码泄露，去改密码"
- 点"去修改密码"弹出改密码窗口，改完强制重新登录
- 谁都不点，新设备就一直进不来；两边谁先点"允许"，另一边的框自动消失

2. **<span style="font-size:18px;color:#fff">新设备登录看到"另一台正在用"的提示，上面写着那台是手机还是电脑、什么浏览器。你点"切到这台"才接管，点"取消"就停在登录页。旧设备那边同时弹一个挡在最前面的框，写着新设备信息，下面红字提醒可能密码泄露，给一个"去改密码"的入口；你点允许，旧设备就下线；点拒绝，新设备进不来。改密码是弹窗改，改完要重新登录。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">新设备 pending 会话由新设备端 POST 确认接管；旧设备端每 5 秒轮询 GET pending-takeover，发现后强制弹框（modal.confirm，不可点遮罩关闭），按钮允许/拒绝，含修改密码链接与 ChangePasswordModal；改密成功后清空会话回到登录。</span>

## 1. 登录冲突时的完整流程

1. 新设备输完账号密码登录，后端查到这个账号当前有一台 is_online=true 的有效会话。
2. 后端不挤人，先给新设备建一条 admission_status='pending' 的会话，记录新设备信息（浏览器、系统、安装标记），并下发登录 cookie。
3. 新设备前端拿到 /me 返回的 admissionStatus='pending'，弹出"切到这台设备"框，锁住页面，不能用任何业务功能。
4. 旧设备每 5 秒调一次查询接口，发现有一条 pending 请求，弹出强制确认框。
5. 结果三选一：
   - 新设备点"切到这台" → 新会话变 active+online，旧会话全部 is_online=false；旧设备下次请求发现自己离线。
   - 旧设备点"允许并下线本机" → 同上。
   - 任一边点"拒绝/取消" → pending 会话标记为 denied，新设备轮询到后显示"已被拒绝，请重新登录"。
6. 两边谁都不点：新设备一直 pending、不能用；旧设备照常使用，但那个确认框一直挡着。

4. **<span style="font-size:18px;color:#fff">简单说：新设备先进一个"待批准"状态，旧设备收到询问。新设备自己也能直接批准自己接管（因为是账号本人在新设备上操作），旧设备也能批准或拒绝。哪边都不批，新设备就停着。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">pending 会话由 registerSession 在检测到现有在线会话时创建；activate 接口把 pending 提升为 active+online 并把其他会话置离线；deny 把 pending 置为 denied；新设备端轮询 /me 的 admissionStatus，旧设备端轮询 pending-takeover 接口。</span>


## 2. 接口契约

| 接口 | 作用 | 说明 |
|---|---|---|
| POST /api/billing/login | 登录 | 无冲突时照常返回 active；有冲突时返回 admissionStatus='pending' 和当前在线设备信息 |
| GET /api/billing/me | 看自己 | 响应新增 admissionStatus（pending/active/expired）；pending 时前端弹接管框 |
| GET /api/billing/sessions/pending-takeover | 旧设备轮询 | 有 pending 请求返回新设备信息，没有返回空；只旧在线设备可调 |
| POST /api/billing/sessions/:id/activate | 批准接管 | 新设备自助接管，或旧设备允许；把该 pending 变 active+online |
| POST /api/billing/sessions/:id/deny | 拒绝接管 | 旧设备拒绝；pending 变 denied |

5. **<span style="font-size:18px;color:#fff">新设备登进来时如果发现旧设备在线，就先挂起；新设备自己点"切过来"或旧设备点"允许"才放行；旧设备点"拒绝"就把这次登录拒掉。旧设备每隔几秒自动看一眼有没有人想登。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">路由在 scripts/deploy/api-server.mjs 挂载；权限从 JWT 的 sub 和 sid 推导，不接受前端传的 userId。activate/deny 都校验该 pending 会话属于当前用户。</span>


## 3. 两个弹框长什么样

### 新设备端（被挡在登录后）

- 标题："检测到其他设备正在使用"
- 正文：正在线的设备信息（如 "Windows · Chrome，最近在线 10 分钟前"）
- 提示："切到这台设备后，旧设备会自动下线。"
- 按钮：[切到这台设备] [取消]
- 不操作就一直停在这，不能用业务功能

### 旧设备端（强制挡在最前面）

- 标题："检测到新设备登录"
- 正文：新设备信息 + 红字提醒"如果这不是你本人操作，可能密码已经泄露，请立即修改密码。"
- 按钮：[允许并下线本机] [拒绝]
- 底部链接："去修改密码" → 弹出改密码窗口；改完强制回到登录页

6. **<span style="font-size:18px;color:#fff">旧设备这个框不能点外面关掉，必须点允许或拒绝；里面除了两个按钮，还有一行红字和一个改密码入口，改密码是弹窗，改完要重新登录。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">旧设备弹框用 antd Modal，maskClosable=false、keyboard=false；改密码复用现有修改密码逻辑做成 Modal，成功后调 logout 并跳登录页；所有文案走 i18n。</span>


## 4. 边界情况

- 没有其他在线设备：登录直接 active，不弹任何框（保持现状）。
- 同一台设备（同浏览器再次登录）：不弹框，直接恢复在线（保持现状）。
- pending 请求超时：pending 会话 10 分钟没被处理，自动失效，新设备显示"登录确认超时，请重新登录"。
- 旧设备自己关了网页：它不再轮询，新设备仍可自助点"切到这台"接管。
- 两个弹框同时出现：谁先点"允许/拒绝"都生效，另一边轮询到结果后自动关框。

7. **<span style="font-size:18px;color:#fff">同一台浏览器重复登录不打扰；没别人在线时不弹框；新申请拖太久没人理就作废；旧设备就算关了网页，新设备自己点"切过来"也能用。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">同 installation_id 命中已有 active 会话时走原快速路径；pending 会话设置 expires_at=now()+interval '10 minutes'；新设备自助 activate 不依赖旧设备在线。</span>


## 5. 安全要求

- 新设备在 pending 状态下，除了 /me、activate、deny 这几个自己的接口，其他业务接口一律拒绝。
- activate/deny 必须校验会话属于当前登录用户，不能靠前端传编号乱点别人的会话。
- 所有登录、批准、拒绝都写安全日志，不记密码。
- 旧设备弹框里的"修改密码"不跳过身份确认。

8. **<span style="font-size:18px;color:#fff">新设备没批准前只能问自己"批不批准"，不能真用；谁批准、拒绝了谁都记日志；改密码要验原来的密码。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">中间件对 admission_status='pending' 的会话拒绝业务路由；activate/deny 用 JWT sub 校验会话归属；安全事件写 app.security_events；改密码走 Appwrite updatePassword，需先验证当前密码。</span>
