# 用户生成内容与上传素材存在哪

## 1. 这是什么

**<span style="font-size:18px;color:#fff">你生成的图片、视频、音频、文本，以及提供的参考附件和手动上传的素材，都要统一保存到腾讯云。保存成功后，下次打开仍能找到。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">目标方案：全部用户生成结果及上传素材直接写入腾讯云 COS；服务器硬盘不作为正式存储、临时文件中转或失败回退。数据库保存业务记录与对象引用，浏览器只保留缓存和草稿。本文件是已确认的目标规划，尚未代表代码完成接入。</span>

## 2. 用户怎么用

**<span style="font-size:18px;color:#fff">你可以生成图片、视频、音频或文本，也可以上传参考图、参考视频、参考音频、文档等素材。生成或上传完成并保存成功后，内容会出现在对应的作品、素材或历史记录里；关掉浏览器再回来仍能查看，也能下载，分享则按授权规则办理。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">统一覆盖 AI 图片、视频、音频、文本正文，生成输入附件及用户手动上传文件；页面入口按业务类型接入。只有 COS 写入和数据库登记均确认成功，才显示保存成功。分享不等于公开存储桶，读取必须校验用户及空间权限。</span>

**<span style="font-size:18px;color:#fff">内容保存多久、删除后还能恢复多久，需要另行确定。当前不能承诺所有内容永久保存，也不能擅自增加到期自动删除规则。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">保留期限与删除恢复窗口仍是待确认产品规则，参见数据库总览第 14、16 节；存储位置、分类与流程已有目标设计；具体产品限额与期限仍见第 13 节待确认表。</span>

## 3. 数据是怎么流的

**<span style="font-size:18px;color:#fff">保存前先登记是谁的、来自哪次生成，并固定文件编号和位置；内容直接上传腾讯云，检查完整后再标记保存成功。查看时先核对权限，再读取内容；服务器不把这些内容写到自己的硬盘上。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">生成结果可经后端内存流直接写 COS；手动上传和参考附件可采用受限授权直传，或经后端内存流转发。禁止使用服务器临时文件、磁盘缓存或挂载目录作为上传中转。上传前登记 pending 的 file_objects 及来源，上传成功并核验后在事务内补齐业务关联并置为 ready；具体上传接口及重试实现待开发。</span>

```text
AI 生成结果 / 参考附件 / 手动上传素材
  → 先登记待写入文件，固定编号、保存位置及来源
  → 直接写入腾讯云 COS（不落服务器硬盘）
  → 校验上传结果
  → 数据库登记归属、来源、文件位置和状态
  → 返回保存成功
  → 用户查看时校验权限，再读取 COS 内容
  → 最后增加访问加速，先覆盖图片
```

**<span style="font-size:18px;color:#fff">完整的文字结果也保存在腾讯云。列表可以显示简短摘要，生成时用的提示词、模型、时间和内容归属另行记录，方便查找和追溯。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">生成文本正文作为 COS 对象保存；PostgreSQL 保存任务、提示词、生成参数、摘要、对象键、文件类型、大小、校验值及工作空间归属。图片缩略图、视频封面等持久化派生文件同样写 COS，不使用服务器磁盘存储。</span>

## 3.1 按类、按组保存（目标规则，待实现）

**<span style="font-size:18px;color:#fff">正式使用和测试使用的内容分开保存。每个个人空间、团队空间各有自己的位置，再分生成结果、参考附件、手动上传素材、编辑版本和预览文件；每组继续按内容类型、年月和生成或上传批次整理。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">生产与非生产使用独立 COS bucket，并分别配置访问权限；下述目录是对象键前缀，不是服务器文件夹。空间级根路径采用 workspaces/{workspaceId}/，以空间作为所有权边界，上传者单独记录。目标 bucket 名称与 region 在实施时核实。</span>

```text
各环境独立的存储桶
└─ workspaces/{workspaceId}/                 所属个人或团队空间
   ├─ generated/{type}/{YYYY}/{MM}/{taskId}/{fileId}.{ext}
   │                                        生成结果，按任务分组
   ├─ references/{type}/{YYYY}/{MM}/{uploadBatchId}/{fileId}.{ext}
   │                                        新上传的参考附件，按上传批次分组
   ├─ uploads/{type}/{YYYY}/{MM}/{uploadBatchId}/{fileId}.{ext}
   │                                        手动上传素材，按上传批次分组
   ├─ edits/{type}/{YYYY}/{MM}/{editId}/{fileId}.{ext}  编辑产生的新版本
   └─ previews/{sourceFileId}/{variant}/{fileId}.{ext}
                                            缩略图、封面等，按原文件分组
```

**<span style="font-size:18px;color:#fff">图片、视频、音频、文字、文档和其他允许上传的文件各归各类。比如一次生成四张图，四张放在同一次任务下；同批上传一张图和一段音频，分别归类，但仍能查出它们属于同一批。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">generated、references、uploads、edits 统一使用类型枚举 images、videos、audio、text、documents、other；生成文本正文归 text，PDF、Word 等文件归 documents，其他已允许格式归 other，不能借 other 绕过上传格式限制。后端按实际格式验证类型与扩展名，不仅信任客户端文件名。年月按首次创建记录的 UTC 时间生成，重试沿用原时间、批次和对象键。</span>

| 内容 | 来源目录 | 类型目录示例 | 分组依据 |
|---|---|---|---|
| AI 图片、视频、音频、文本结果 | generated | images、videos、audio、text | 生成任务编号 |
| 新上传的参考图、参考视频、参考音频、文本或文档 | references | images、videos、audio、text、documents | 上传批次编号，并记录任务引用 |
| 手动上传素材 | uploads | images、videos、audio、text、documents、other | 上传批次编号 |
| 用户编辑、裁剪等产生的新文件 | edits | images、videos、audio、text、documents、other | 编辑操作编号 |
| 缩略图、视频封面、其他预览文件 | previews | 不使用类型层；使用预览规格 variant | 原文件编号 |

**<span style="font-size:18px;color:#fff">你的原文件名会保留用于显示，但实际保存时使用不会重复的编号。同名文件不会互相覆盖；修改内容产生新版本，原来的版本不会被悄悄替换。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">对象键由后端生成，仅采用受控分类、经授权校验的空间编号和唯一 ID，不拼接用户输入的文件名、邮箱或项目名。原名作为展示元数据保存。新内容或新版本使用新 fileId；同一次写入重试复用已分配的 fileId 与对象键，并校验内容一致性。预览 variant 为后端定义的缩略图或封面规格，新预览版本使用新 fileId。</span>


## 3.2 项目、收藏夹与素材复用（目标规则，待实现）

**<span style="font-size:18px;color:#fff">你可以按项目、收藏夹和自定义分组整理内容。改名、移动分组只是改变页面里的归类，不搬原文件。同一份素材用到多个项目，或再次选为参考附件，都可以复用原文件。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">COS 保存稳定对象路径；项目、集合和任务用途由数据库引用关系管理。现有 asset_references 只记录资产到资产的来源关系，collections、collection_items 记录集合成员；项目关联与任务参考输入需补充专门关系，见数据库总览第 10.4 节。自定义分组复用集合能力，层级与排序等扩展在实现时确认，不将此规划当作已建表。已有素材被选作参考时只增加经授权的引用，不复制到 references；只有新上传的参考文件使用 references 前缀。来源目录表示首次入库来源，不随用途变化搬迁。</span>

**<span style="font-size:18px;color:#fff">团队成员离开不会改变文件属于哪个空间。跨空间使用素材要先获得授权；删除一个项目里的引用，也不能把其他项目仍在使用的原文件删掉。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">workspace_id 为所属空间，created_by 或 uploaded_by 记录操作人；团队成员退出不改对象键。跨空间分享保留原归属并验证显式授权，复制为独立资产需重新授权与创建版本，不做未经授权的跨空间去重。删除对象前检查全部有效引用及保留规则；前缀分类不替代后端权限检查。</span>

## 3.3 目录与数据库字段对应（设计已补充，待实现）

**<span style="font-size:18px;color:#fff">文件放得整齐，还要记清它是什么、从哪里来、属于谁、在哪些地方使用。查图片或某批上传的内容时，直接查这些记录，不靠拆文件地址猜分类。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">下表是 COS 前缀与数据库字段的目标映射。已有字段继续复用，新增字段和关系见数据库总览第 10.4 节；筛选使用数据库字段，object_key 是文件定位依据，不能替代分类与权限事实。路径在首次写入时生成并保持稳定。</span>

| 保存层级 | 数据来源 | 当前与目标 |
|---|---|---|
| 各环境独立存储桶 | 环境配置及 file_objects.bucket | bucket 字段已有；独立 COS 配置待接入，不接受客户端任意指定 |
| workspaces/{workspaceId} | file_objects.workspace_id | 已有，后端校验空间权限 |
| generated / references / uploads / edits / previews | 拟新增 file_objects.source_kind | 分别映射 generated / reference_upload / manual_upload / edited / derived |
| images / videos / audio / text / documents / other | 拟新增 file_objects.media_type | 数据库取值 image / video / audio / text / document / other，路径通过固定映射转换 |
| YYYY/MM | file_objects.created_at | 已有，首次创建的 UTC 年月，重试不重新分配 |
| taskId | generation_outputs.task_id 与 file_id | 已有字段；目标是预先关联待写入文件与生成任务，成功后才允许读取 |
| uploadBatchId | 拟新增 file_objects.upload_batch_id → upload_batches.id | 同一次上传共同批次；批次可包含不同类型，单文件成败分别记录 |
| sourceFileId / variant | 拟新增 file_objects.source_file_id / preview_variant | 预览同时必填；编辑文件只填 source_file_id 指向基础文件，禁止自引用 |
| editId | 拟新增 file_objects.edit_id | 同一次编辑使用同一编号，重试沿用 |
| fileId.ext | file_objects.id 与校验后的 mime_type | 已有；扩展名由受控格式映射生成，不取用户提供的路径 |

**<span style="font-size:18px;color:#fff">“这是一张图片”和“这是上传来当参考的”是两件事，要分别记录。图片后来被另一个项目使用，只增加使用记录，不改变它最初的保存分类。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">media_type 表示实际内容类别，source_kind 表示首次入库来源；mime_type 表示具体文件格式。现有 asset_type、output_type 按统一类别映射校验，但任务 task_type=agent 仍表示执行能力，不能强行当作文件类型。已有素材作为参考由拟新增 generation_inputs 关联，不修改 source_kind，也不复制到 references。</span>

**<span style="font-size:18px;color:#fff">没有上传完成的文件不能显示为可用。一次上传十个文件，其中一个失败，就记录那个文件的失败，重试时继续使用原编号，其他成功文件不必重传。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">file_objects.status 已有 pending、ready、deleting、deleted，目标新增 failed 并补重试信息。仅 COS 对象核验及关联登记成功后进入 ready；批次状态由文件状态汇总，不作为第二套可独立修改的事实。COS 与数据库失败补偿、幂等约束和删除引用检查详见总览第 10.4 节。新设计尚无迁移或运行验收。</span>

<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">当前 object-store.mjs 默认 local，S3 实现仍为占位；api-server.mjs 的生成图片和资产上传包含磁盘写入路径。旧图片兼容读取仍存在。视频、音频、文本、参考附件和手动上传各入口均需逐项接入验收。未核实本次线上实际配置。</span>

**<span style="font-size:18px;color:#fff">已有交付记录提到腾讯云备份验证通过，但备份成功不代表新生成的内容已经直接保存在腾讯云。作品查看、下载和分享，也要按每种内容分别验证。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">COS 备份副本与业务对象主存储分开判断。历史文档描述过图片列表、大图、下载和分享入口；不能据此宣称全部内容类型已支持。直接分享到微信、微博以及 CDN 加速仍未在本规划中验收。</span>

## 5. 存在哪最好

**<span style="font-size:18px;color:#fff">已选定腾讯云保存全部内容。把大文件或完整生成正文塞进业务记录会增加查询和备份负担；放在服务器硬盘又会占用服务器空间。以后增加访问加速时，原文件仍保存在腾讯云。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">统一采用 COS 作为业务内容主存储，PostgreSQL 保存元数据与引用。CDN 是访问加速层，不替代 COS；私有内容加速仍需维持鉴权。容量、副本和备份需独立配置与验证，不承诺无限容量或绝对不丢失。</span>

| 方案 | 作用与取舍 | 当前决策 |
|---|---|---|
| 完整内容塞数据库 | 增加业务查询、传输和备份负担；旧数据需兼容 | 不作为新内容的目标方案 |
| 服务器硬盘 | 占用服务器容量，依赖磁盘及备份恢复 | 历史实现待替换；不作为新内容存储或中转 |
| 腾讯云 COS | 统一保存完整结果、参考附件和上传素材；需控制容量与费用 | 直接接入，作为正式存储 |
| CDN 访问加速 | 加快内容访问，另有配置与费用 | 最后接入，先覆盖图片；COS 保留源文件 |

## 7. 出问题怎么办

**<span style="font-size:18px;color:#fff">保存失败时明确提示失败并允许重试，不能显示保存成功，也不能悄悄把内容改存服务器硬盘。已经上传但登记失败的内容，要能找回来补登记或清理，避免越积越多。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">COS 与 PostgreSQL 不能假定共享数据库事务；需设计幂等重试、未完成状态及孤立对象对账补偿。上传或登记失败必须反馈，禁止 local 磁盘或完整正文入库回退。若需回退代码，只能使用仍符合 COS 直存约束的版本，否则暂停相关写入。</span>

**<span style="font-size:18px;color:#fff">旧代码曾提供把图片改回业务记录保存的开关。这是历史机制，新方案不能继续把它当作出错后的备用保存方式。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">历史 GEN_OUTPUTS_TO_STORAGE=off 会回退到 b64_json；当前代码仍存在该分支，实施 COS 直存时需要移除或禁用新写入回退，保留必要的旧数据读取兼容。</span>

## 10. 上传、文本与无硬盘处理（目标规则，待实现）

**<span style="font-size:18px;color:#fff">上传前先检查格式、大小和剩余空间，再分配保存位置。大文件分段上传，断网后尽量接着传；取消上传时停止后续传输，并清理已经上传的零散部分。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">标准流程：授权与配额预占 → 登记 pending 文件及来源 → 受限直传或后端流式写 COS → 后端核验实际对象 → 数据库提交关联及 ready → 返回保存结果。大视频、音频使用 multipart upload，持久化上传会话与分片信息；恢复时重新校验账号、空间、对象键及 COS 会话。取消与完成必须串行校验状态，过期及废弃分片进入补偿清理。客户端上报完成不等于保存成功。限额及超时数值由第 13 节确认后配置。</span>

**<span style="font-size:18px;color:#fff">文件经过服务器时，要一小段一小段转发，不能整段视频全部装进内存。预览图、视频封面和格式检查同样不能偷偷写入服务器硬盘；暂时无法处理的格式要明确提示。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">后端采用有界流式缓冲、背压、并发及超时限制，不使用整文件 buffer/base64。浏览器直传为允许来源配置 CORS，临时写授权限制对象键、操作和有效期；长期密钥不发前端。核验格式、内容长度及校验值；ETag 不假定等于文件内容校验和。缩略图/封面优先使用经验证的 COS 处理能力或无磁盘流式处理；格式需要随机访问且不能无盘处理时拒绝该处理或标记预览不可用，不承诺所有格式均支持。反向代理请求缓存、上传中间件、处理工具临时文件和应用日志均纳入无用户内容落盘验收。</span>

**<span style="font-size:18px;color:#fff">文字可以边生成边显示，但未保存的部分要明确标出来。中途断开时不能把半段文字当成完整结果；用户编辑已保存文字，会产生新版本，不覆盖原来的内容。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">生成文本按 UTF-8 与受控格式保存；流式显示与持久化确认分离。完整结束标记、对象核验和数据库提交齐备后才标记 complete。若产品确认保留中断正文，则写独立 COS 对象并标记 partial，且不作为成功生成结果；未选择保留策略前不承诺断流内容可恢复。浏览器断开不自动等于后台任务取消。编辑使用新 fileId 与 asset_version，保存时校验基准版本，冲突明确提示，禁止最后提交者静默覆盖。阶段信息见数据库总览第 10.5 节。</span>

## 11. 查看、下载、分享与版本（目标规则，待实现）

**<span style="font-size:18px;color:#fff">文件传好、内容检查通过、你有权查看，是三个不同条件。需要的条件都满足才能使用或分享；文件名、保存地址和是否能打开，不能代替权限检查。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">COS 桶保持私有。读写接口分别校验空间权限、文件生命周期与操作所需审核状态；ready 仅代表保存完整，不代表 approved 或 public。内容检查待完成、失败和被拒绝均不可按通过处理。下载与预览采用经授权的短期签名 URL 或鉴权代理；数据库保存稳定对象引用，不存签名 URL 作为永久地址。浏览器展示文本和文档需转义或隔离，不能把用户文件作为站点可信脚本执行。</span>

<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">访问方案应支持 Range 请求、正确 Content-Type 和下载文件名；链接刷新重新鉴权，禁止无限刷新失效授权。短期直读签名不是即时撤销机制；若产品要求即时撤权，应选每请求鉴权的代理/边缘方案。后续 CDN 保留私有源站与访问鉴权，定义链接有效期、缓存隔离和失效策略，不可因缓存绕过撤权。具体期限见第 13 节。</span>

**<span style="font-size:18px;color:#fff">项目使用当时选定的作品版本。作品后来修改了，旧项目保持原样；需要新版时由用户明确切换。同一次生成用过的参考文件也保持不变，方便以后核对。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">项目素材关系固定 asset_version_id，不默认跟随最新版本；generation_inputs 固定不可变 file_id。切换版本重新授权并校验该版本属于所选资产，记录操作者及时间，按项目交互规范反馈。收藏可面向作品浏览，但不能作为项目执行版本的依据。</span>

## 12. 保存失败、额度与上线验收（目标规则，待实现）

**<span style="font-size:18px;color:#fff">模型生成了内容，但保存失败时，要显示“生成完成，保存待恢复”，不能显示全部完成。重试保存应优先找回原结果，不能悄悄重新生成并再扣一次费用。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">区分供应商执行结果、文件持久化状态和账务结算状态。保留上游任务编号及可恢复输出定位，敏感临时地址须受控且不写日志；短期源地址失效风险进入重试时限设计。先核验 COS 是否已成功写入，再补登记或从原上游结果补传；进程崩溃且原结果不可取回时明确记录不可恢复，不承诺零丢失。重新调用模型属于新生成，必须另行确认。扣费、额度释放或补偿沿用计费与任务一致性规范；本场景具体交付和退款口径列入待确认表，不由文件状态自动决定。</span>

**<span style="font-size:18px;color:#fff">同一份文件被多个项目使用，只保存一份。空间满了不能靠同时上传绕过限制；上传失败释放预留空间，删除后什么时候返还空间，要先定清楚。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">容量按物理对象计量，不按引用次数重复计量；并发上传采用空间级原子预占，核验后按实际大小结算，失败/取消幂等释放，状态未知先对账。不得直接复用 image_gen 次数作为字节额度。原件、预览、历史版本和回收站是否计入用户套餐属于第 13 节决策，计量明细需能追溯 file_id。生成文件大小未知时使用受控上限预占或追加校验，禁止不限量写入。</span>

**<span style="font-size:18px;color:#fff">正式切换前，要分别试过各种内容，还要试断网、取消、保存失败和恢复。旧文件只有核验迁移成功后才能安排清理；出问题时暂停受影响的写入，不改回服务器硬盘保存。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">验收覆盖混合批次、断点续传、取消与完成竞争、空间并发超限、文本断流及编辑冲突、项目版本固定、审核未通过、签名到期及分享撤销、COS 成功但数据库失败、进程重启补偿、所有入口无磁盘落盘。监控 pending 滞留、失败率、孤立对象、废弃分片、预占泄漏、容量与费用异常，告警阈值实施前配置。迁移/备份/恢复按《备份回滚恢复》第 8 节执行；测试通过前保持待实现状态。</span>

## 14. 八处衔接规则（目标设计，待实现）

### 14.1 保存进度只按一套事实显示

**<span style="font-size:18px;color:#fff">文件是否存好、这次传输到哪一步、模型是否生成成功，各记各的。页面从这些记录计算进度，不再另外维护一套“保存成功”。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">file_objects.status 负责文件生命周期；upload_sessions.status 负责传输；生成尝试负责供应商执行结果；generation_tasks.status 负责产品任务；审核及账务各自独立。persistenceStatus 按完整输出清单及文件状态派生，只读，禁止独立写 output.archive_status 形成双权威。状态映射见数据库总览第 10.6 节与系统一致性规范第 3 节。</span>

### 14.2 每份生成结果都有固定位置

**<span style="font-size:18px;color:#fff">一次要四张图，就记清要求几张、模型实际返回几张、每一张保存到了哪一步。只保存三张时，能查出缺的是哪张；重试只补那一张，不重新生成全部内容。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">记录 requested_output_count、供应商确认的 returned_output_count 和 response_complete；generation_outputs 使用稳定 output_index 与上游输出标识映射，每次调用尝试内编号唯一。未拿到内容可先保留空 file_id 的输出槽位，不能把缺失文件忽略后误判全量成功。数量未知使用 NULL，不拿已保存数量反推应交付数量。少返、超返、partial 与部分计费仍按第 13 节产品决策处理。</span>

### 14.3 历史记录不永久挡住删除

**<span style="font-size:18px;color:#fff">项目正在用的文件先不能直接删；但“以前生成过它”的历史记录，可以保留一个“文件已删除”的提示，不必因此永远保留原文件。备份中的保留也与用户能否查看分开。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">引用分为活动使用、历史追溯、备份保留。活动画布节点、运行/排队任务输入、有效分享及其他未释放的业务用途阻止直接清理；已结束任务记录在满足保留策略后可降为历史引用，不阻止物理清理。file_objects 元数据行保留 deleted 墓碑，generation_outputs 等外键继续指向该行，不伪造文件可读。历史引用失去复现能力须明确提示；切换为历史、解除占用、备份保留均留审计。未确定保留期限不自动启用清理。</span>

### 14.4 画布每个位置固定自己的版本

**<span style="font-size:18px;color:#fff">同一个画布可以左边放原图、右边放修改图。每个位置记住自己选的版本，换右边的图不会连左边一起换。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">新增节点使用关系固定 node_id、slot_key、asset_version_id 和 file_id；项目素材成员版本是选用默认值，不覆盖已建立的节点引用。节点位置、附件槽位及版本关系详见数据库总览第 10.6 节。执行时读取节点固定引用，禁止临时取资产最新版本。</span>

### 14.5 编辑版本单独分类并保留来源

**<span style="font-size:18px;color:#fff">修改生成文字、裁剪图片后得到的是编辑版本，不是预览，也不是又调用了一次模型。新版本有自己的保存位置，还能查回修改前的文件。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">新 source_kind=edited，保存到 edits/{type}/{YYYY}/{MM}/{editId}/{fileId}.{ext}。同一编辑操作复用 edit_id；source_file_id 指向基础文件，asset_versions 保存版本关系。原文件 source_kind 不变，新文件记录自身直接来源；多输入编辑经专门编辑输入关系记录，不能将多个文件 ID 塞入单列。只有确实调用 AI 的新任务才走 generated 及相应计费流程。</span>

### 14.6 保存后不能被旧请求换掉内容

**<span style="font-size:18px;color:#fff">文件保存确认后，查看、检查和下载都要指向当时确认的那一份。即使旧上传请求晚到，也不能改变已经保存的作品。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">客户端写权限不得覆盖已发布对象；目标直传桶启用并验证对象版本保护，保存时固化 storage_version_id 与 checksum，读取、审核、预览和备份显式绑定该版本，禁止默认读取最新版本。迟到上传产生的其他版本不得自动更新已提交记录，须纳入对账与容量核查。若无法验证版本保护或条件写语义，改用隔离上传键并由受控后端发布到只读最终键，不允许带风险上线。取消后写凭据在有效期内可能仍可用，须等待失效并核查迟到对象后完成清理，不能靠数据库锁宣称云端请求已停止。</span>

### 14.7 调用模型前再检查参考文件

**<span style="font-size:18px;color:#fff">选参考图时能用，不代表任务真正开始时仍能用。发给模型前再检查一次；如果分享已撤销或文件已删除，就停止调用并说明原因。已经发给外部模型的内容，不能靠撤销站内分享收回来。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">生成尝试 dispatch 前重新验证任务发起人当前权限、空间成员状态、用途授权、文件版本、生命周期及检查状态；记录授权判定与派发时点。授权验证、执行占用和撤权采用受控并发边界；撤权先完成则不得 dispatch，派发已完成则标记在途并尽可能取消后续处理，不承诺收回第三方内容。当前 generation_inputs 仅允许同空间，跨空间不能仅凭可读链接插入；采用明确授权的独立复制后使用，跨空间直接引用仍需专门设计，不宣称已支持。</span>

### 14.8 失败之后有明确接手人

**<span style="font-size:18px;color:#fff">保存、检查或清理失败后，由后台记录并接着处理。服务重启也能找到没完成的工作；多次失败就进入待人工处理列表，不让页面永远只显示“恢复中”。</span>**<br>
<span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">文件恢复作业持久化，采用事务内入队或 outbox，并由定期对账补漏；覆盖补传、核验、内容检查、预览、删除与分片清理。领取带租约与递增执行代号，旧执行器失去租约后不得提交结果；云端副作用由稳定键/版本校验去重。失败退避重试，超过配置阈值进入 needs_attention 并告警，保留原 file_id/output 槽位供人工重放。人工操作需权限、理由和审计，不自动重新调用收费模型。字段、状态及验收见总览第 10.6 节。</span>
