## 4. 以后必须复用的检查规则

1. 新表先写“事实归属”，后写字段；已经有权威表时，不新增第二个可写副本。
2. 文件存在、接口定义、路由挂载、写入成功和线上验收是五种不同证据，不能混用。
3. 每个空间关联同时审查归属与记录编号；跨空间只能走明确授权关系。
4. 任何外部收费操作都考虑超时结果不明、重复执行、取消和迟到回调。
5. 迁移预案必须回答“目标已产生新数据之后怎么办”，不能只写换回连接地址。
6. 所有完成声明要写验证层级；格式检查通过不能表述成代码、性能或迁移通过。
7. 新功能同步更新总览、所属模块和受影响的横向规范，避免只在最后不断追加另一套互相矛盾的规则。

## 5. 第二轮审查新增结论

| 发现 | 修订 |
|---|---|
| Appwrite 身份与旧 qingyu_server JWT/SQLite 身份并存 | 增加身份桥接规则：目标业务只认 Appwrite 映射出的内部 user_id；旧 JWT 只能短期兼容，不能绕过新权限 |
| 平台 API Key 与用户自定义 AI 渠道没有明确边界 | 增加 ai_channels 与 provider_credentials 的所有者和访问边界，防止用户密钥变成全平台密钥 |

| 总览仍有 team、teams 和 models 的混用 | 统一为 teams、ai_models，并把 ai_channels 放入 AI 目录 |

本轮仍只审查和修改规范，未修改旧后端、Appwrite 配置或线上数据库。身份桥接、权限隔离和新增安全记录必须在实现阶段通过端到端测试后才能声称完成。

## 6. 第三轮：第一性原理审查结论

本轮从“系统必须保证什么”倒推，而不是只检查表结构。新增独立文档《第一性原理与安全边界审查》，确认以下问题属于上线阻断项：代理和 Agent 网关缺少用户级鉴权与空间隔离、身份体系并存、前端保存长期密钥、计费接口与后端实现不完整、平台 API Key 明文读取、外部副作用缺少统一幂等和任务持久化。审查还补充了统一请求生命周期、失败语义、扩容边界、观测字段和第一性原理验收清单。

本轮没有修改业务代码。它的结论是：在 P0 安全和一致性问题修复并验证前，不能把代理、Agent、真实收费或团队共享当作可上线能力。

## 8. 第五轮：预占、恢复与数据完整性

已补预占与现金扣款区别、数值示例、守恒公式、批次到期、部分结算、团队预算和迟到回调处理。原先只有 available/reserved 的方案无法完整表达多来源及到期规则，现以 quota_grants/quota_allocations 补来源，不另建一套可编辑余额。

新增备份恢复执行规范：区分事务撤销、业务冲正、应用回滚与数据恢复；区分逻辑备份与物理备份加 WAL；覆盖 Appwrite、对象文件、Agent、密钥、外部回调和删除撤权记录。恢复后必须重新核对真实支付与上游调用，不直接重放旧任务。单租户误删优先旁路恢复，避免影响其他用户的新数据。

新增完整性矩阵，列出部门循环、邀请席位、审批参数绑定、文件多入口引用、导入映射和外部源等遗漏。保留期、取消和退款计价、最长冻结时间、备份存储与预算仍待明确，不能假称全部完成。技术恢复依据核对 PostgreSQL 16 官方备份文档；本轮未配置自动备份、未跑恢复演练或扣费代码。

## 9. 第六轮：多设备会话与实时同步

新增《多设备会话与实时同步规范》，把 Appwrite 身份会话、PostgreSQL 业务准入、设备摘要、账号级撤销版本和安全审计分开。明确建议的会话上限只是待定策略，不把登录设备数与任务并发数混为一谈；满额登录、指定设备退出、退出全部、提供方撤销失败和恢复后的旧会话均有处理规则。新增服务端提交后写 outbox、授权订阅、游标补齐、快照重同步、版本冲突和幂等重试规则，避免现有 WebDAV 时间戳合并被误当成实时权威同步。

## 10. 第七轮：第一性原理与故障闭环复核

继续从“什么事实绝不能错”倒推多设备和实时同步：身份必须由服务端确认，权限必须在操作时有效，事务提交才算保存成功，通知不能先于事实，重复请求不能重复副作用，撤销和删除不能被旧缓存复活，资源版本、账号安全版本和恢复代次不能混用。新增失败矩阵，区分过期、超时未知、outbox 积压、游标过期、版本冲突、权限途中撤销和恢复后旧请求，明确哪些可用同一幂等键重试、哪些必须停下让用户确认。

补充连接、消息、缓存的敏感数据边界，关键记录的 request_id/workspace_id/版本追踪要求，事件积压、撤销重试、unknown 操作和 outbox 守恒监控，以及迁移、重放、补偿和日志脱敏边界。新增实施闸门，要求统一鉴权覆盖业务 API、文件、SSE/WebSocket、Agent 和管理接口，并通过恢复、双写迁移、账号切换和乱序消息测试后才能宣称完成。

本轮仍只优化规范和交叉审查，未修改业务代码、Appwrite 配置或线上数据库；版本 0.7 的规则是实施约束，不是现网能力证明。

## 12. 第八轮：线上连接链路核对与应用角色准备
