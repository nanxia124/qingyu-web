# 表单与密码校验规范

## 规矩

1. **<span style="font-size:18px;color:#fff">全站所有让用户输密码的框，右边都要有一个小眼睛图标，点一下能看见明文，再点一下藏回去。每个密码框的显隐各自独立。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">统一密码输入组件 src/components/PasswordInput.tsx，右侧 lucide Eye / EyeOff 图标切换 input type=password / text。三个框（旧密码、新密码、确认新密码）各自维护自己的 visible 状态，互不影响。</span>


2. **<span style="font-size:18px;color:#fff">改密码、重置密码、还有 API Key 这种敏感输入框，一律用同一个密码框组件，不要每个页面自己写 input。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">统一组件 src/components/PasswordInput.tsx。使用位置：管理员后台修改密码弹窗 src/pages/admin/AdminDashboard.tsx、用户端安全设置页 src/pages/account/SecurityPage.tsx、忘记密码重置页 src/pages/ResetPasswordPage.tsx、后台添加/编辑 API 渠道的 api_key 输入框。页面里不再直接写 &lt;input type="password"&gt;。</span>


3. **<span style="font-size:18px;color:#fff">新密码最少 8 位，全站一个数。不要后台 8 位、用户端 6 位这种不一样的规矩。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">最少 8 位统一为常量，三处共用。原 SecurityPage / ResetPasswordPage 的 6 位校验一律改为 8 位。</span>


4. **<span style="font-size:18px;color:#fff">改密码时要输旧密码，而且旧密码不能为空；忘记密码走邮件链接进来重置时，不用输旧密码。这是业务区别，不是规矩不一致。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">需要旧密码的场景：AdminDashboard 修改密码弹窗、SecurityPage 安全设置改密码。不需要旧密码的场景：ResetPasswordPage（邮件 token 重置）。旧密码为空时前端直接拦，不发请求。</span>


5. **<span style="font-size:18px;color:#fff">必填项空着、或者填错了，用户点提交之后，那个出问题的输入框要红色高亮，框下面红字写清楚错在哪，光标自动跳到第一个出错的框。不能只在页面顶上弹一句笼统的话让用户自己找是哪个框错了。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">错误态：输入框加 ring-1 ring-red-500（用外发光，不加实线 border，遵守全局禁描边规矩），框下加 text-xs text-red-400 错误文案。提交时按字段顺序校验，遇到第一个错误就 focus() 对应 input 并 return，不再继续。顶部那条红色错误条（pwError）保留作为后端返回错误的展示位，前端字段错误改为就地显示。</span>


6. **<span style="font-size:18px;color:#fff">两次新密码对不上这种问题，用户在第二个框里打字的当下就提示，不要等点了提交按钮才报错。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">confirmPassword onChange 时：若 newPassword 非空且 !== confirmPassword，立刻在确认框下显示"两次新密码不一致"；用户改到一致或清空，错误消失。新密码长度不足 8 位的提示也在新密码框就地显示。</span>


7. **<span style="font-size:18px;color:#fff">页面刚打开、用户还没动的时候，不要一片红。错误只在两种时候出现：用户点了提交按钮，或者用户在某个框里开始打字之后。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">引入 touched / submitted 标记：初始不显示错误；onSubmit 后 setSubmitted=true 触发全量校验；onChange 时清除该字段错误。</span>


8. **<span style="font-size:18px;color:#fff">错误提示文字一律走多语言，不在组件里写死中文。新增的文案（请输入旧密码等）要补全所有语言文件。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">文案 key 沿用 pages.admin.dashboard.* / pages.account.security.* / pages.resetPwd.*，新增 key 同步补全 src/canvas/i18n/locales/ 下全部 17 个语言文件。</span>


9. **<span style="font-size:18px;color:#fff">后台添加/编辑 API 渠道的必填项，也照第 5 条来：空了就那个框变红、框下红字，光标跳过去。不要再只弹一个右上角的 toast 让用户自己猜。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">AdminDashboard 中 handleAdd 里 name / base_url / api_key 三个必填字段：原 message.error(fillRequired) 改为 setFormErrors 字段级错误，对应输入框 ring-1 ring-red-500 + 框下 text-xs text-red-400。Maizi 上游配置是可选配置，没有必填校验，不做字段级报错。后端返回的报错仍走 message.error。</span>


10. **<span style="font-size:18px;color:#fff">新密码不能只是一串数字或一串字母，必须同时有字母和数字。但不要求大小写混合，也不要求加特殊符号。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">校验规则：长度 ≥8，且必须同时匹配 /[a-zA-Z]/ 和 /\d/。不强制大小写、不强制 !@#$ 等特殊字符、不做 90 天强制改密、不做历史密码重复限制。该规则在三处改密码/重置页统一复用。</span>


11. **<span style="font-size:18px;color:#fff">忘记密码只走邮箱，不做手机号找回。管理员后台不做网页忘记密码入口，忘了密码由站长 SSH 上服务器直接重置。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">普通用户走 AuthModal 忘记密码 → Appwrite recovery 邮件 → /reset-password 页设新密码。不接短信服务商、不做国际短信、不做国家区号选择。管理员账号（postgresBilling.admin_accounts）独立于 Appwrite，不绑邮箱、不做网页找回；密码遗忘由站长 SSH 到 ubuntu@43.160.249.6，在服务器上直接改库中 password_hash 为新密码的 bcrypt/argon2 哈希。</span>


12. **<span style="font-size:18px;color:#fff">两次新密码完全一致时，确认框下面要出绿色小字告诉用户对得上；对不上就回到红字错误；两个框只要有一个空着就什么都不显示。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">渲染时判断：newPassword 与 confirmPassword 均非空且相等 → 确认框下 text-xs text-green-400 显示 i18n key pwMatch；有 confirmError 时优先显示红色错误；空值不显示。三处改密码/重置页统一。</span>


13. **<span style="font-size:18px;color:#fff">旧密码输错了，错误要直接标在旧密码框下面，光标跳回旧密码框，不要在页面顶上弹一条红条让用户猜是哪错了。其他错误（网络、服务器问题）还是走顶部红条。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">AdminDashboard 改密码 catch 里判断 err.message 含"原密码"则 setPwOldError 并 focus pwOldRef；SecurityPage 里判断错误消息匹配 /password|密码|current|old/i 则 setOldError 并 focus oldRef；其他错误仍走顶部 message / pwError 红条。</span>


14. **<span style="font-size:18px;color:#fff">浏览器自动填表单时会硬盖一层黄底黑字，跟深色主题撞色。全局样式里要把这层黄底盖成跟输入框一样的颜色，圆角保持不变。</span>**<br>
   <span style="display:inline-block;font-size:12px;color:#666;transform:scale(0.35);transform-origin:left top;line-height:1">src/index.css 末尾覆盖 input:-webkit-autofill 系列：-webkit-text-fill-color 与 caret-color 用 var(--color-secondary-foreground)，-webkit-box-shadow: 0 0 0 1000px var(--color-secondary) inset 盖黄底，border-radius: inherit 保持圆角，transition background-color 5000s 过渡。深浅主题自动跟随 CSS 变量。</span>
